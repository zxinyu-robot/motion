## 1. 产品定位与愿景

- **一句话定位**：ForkSpatialLink 是面向弱网、无 GPS 环境的空间数据流中间件；当前从 **OctVox 增量 → Spatial Token → x86 VLN → 本地安全执行**切入，协同网关为后续产品形态。
- **后续产品愿景【proposal】**：**模组 + 网关**；“连接外部接口后受控部署、减少预先建图依赖”是目标，不是当前已验证的零配置能力。
- **核心差异化**（对标仙工的软肋）：
  1. 仙工需要**预先建图** → 本产品目标**免预先建图**（前端在线 + 后端网关离线增量建图）。
  2. 仙工在狭窄货道等场景**轨迹优化不灵敏** → 本产品聚焦弱网/边缘实时协同。
  3. 市场方案多为**同平面**分布式协同 + 顶层 RPC 调度 → 本产品瞄准**异构平面 + 异构本体**的高集成化协同。
- **当前 P0 验证场景**：同层平面办公场景下的 Go2 单机 Token→x86 VLN→本地安全执行闭环；多机协同为 Swarm Gate 通过后的后续验证。

## 4. 市场痛点与本项目的解法


| 痛点                                | 本项目解法                          |
| --------------------------------- | ------------------------------ |
| 1. 本体厂商只做底层运动控制，集成商难利用底层接口，缺统一中间件 | 版本化 Spatial Token 契约 + x86 Adapter；传输层按 Benchmark 选择 |
| 2. 缺异构平面高集成化协同系统                  | 异构平面分三优先级（见 §6.4）              |
| 3. 方案需在现有平台落地                     | 仿真先行的 WBS 工作分解（见 §9）           |


**异构平面三优先级：**

1. 优先用开源框架解决**不同坐标系融合**；
2. 解决**不同运动学类型混编**（足式 / 轮式 / 人形）；
3. **不同楼层 / 高度层协同**（当前技术尚不明朗 → 视为研究攻关点，见 §8）。

## 5. 系统技术架构



### 5.1 总体架构（前后端分离 + 边端金字塔）

```
本体端（前端 · 在线）                   网关端（后端 · 离线 · 调度大脑）
──────────────────────                 ─────────────────────────────────────
· SLAM 前端里程计估计                    · SLAM 后端一致性约束优化（位姿图 / BA）
  (VIO / LIO，轻量在线)                  · 增量式建图（免预先建图）
· 特征 / 关键帧提取                       · 多机回环检测与地图融合
· 运动控制接口适配              ──DDS──▶  · 语义理解与规划（复用 LL3DA，见 §7）
                                        · VLN/VLA 模型（MADTP 压缩加速，见 §7）
                                        · 多机协同调度（自研 + 群体智能）
```

- **拓扑**：不采用多机点对点（P2P），采用**边端分层金字塔**结构（本体 → 边缘网关 →（可选）云）。
- **前后端分离**：前端只负责在线（本体算力有限、时间敏感）；后端重计算（回环、全局优化、地图融合）放到网关，参考 edgeSLAM2 / ViT-NeRF edge 等边缘辅助 SLAM 范式，但差异化在**多机协同 + 免建图**。



### 5.2 通信中间件

- **P0 基线**：现有 IP 网络 + WiFi；具体数据面由 P0-B/D Benchmark 记录，不预设“开箱即用 Token 网络服务”。
- **契约不变量**：`VoxelTransaction / TokenSequence` 与具体运输层解耦；更换 Fast DDS、Zenoh、QUIC 等候选不得改变空间语义。
- **低拷贝边界**：只主张减少原始点云与中间大对象复制；序列化、内核协议栈与对端接收仍有写入，不宣称端到端零拷贝。
- **后续候选**：DDS-TSN、5G/Mesh/MANET/6G 仅在适配 Gate 与 Benchmark 证明收益后进入，不是 P0 前提。

## 6. 核心技术线拆解



### 6.1 SLAM 流水线（前端里程计 + 后端一致性约束）——分场景选型


| 场景       | 主流线                 | 说明                        |
| -------- | ------------------- | ------------------------- |
| 高端（人形）   | **视觉为主**            | 使用环境与交互方式决定；亦兼容搭载激光的本体    |
| 中端（工业巡检） | **激光为主，激光+视觉融合为方向** | 结合 UWB 脉冲定位标签 + 视觉标签增强鲁棒性 |
| 低端       | **传统 2D SLAM**      | 成本敏感场景                    |




### 6.2 SLAM 作为几何底座 + 上层语言/动作模型

- SLAM 提供导航移动的**几何约束底座**，上层接 VLN / VLA。
- 传统做法需要 encoder-decoder 做"几何 ↔ 语言"翻译，带来信息熵损失。
- **后续研究假设【proposal】**：评估 SLAM 几何状态与任务相关空间记忆 / 3D-LLM 的组合；当前不宣称已形成动作条件 World Model，也不把模型训练纳入 P0。



### 6.3 单机 SLAM 前后端分离共享资源协同

- 前端在线、后端网关离线；目标是在在线增量建图成立后减少对预先建图的依赖【proposal】。共享内存与免预先建图能力均须由具体实现和 Benchmark 验证。



### 6.4 异构平面协同（差异化核心）

- 坐标系融合 → 运动学混编 → 跨楼层/高度层（见 §8 攻关）。
