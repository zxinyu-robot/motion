### 1.1 技术背景

移动具身智能机器人在现场一边走一边建图，但「大模型/世界动作模型」算力放在旁边的电脑或边缘服务器上。  
现在常见几类别扭：

1. **传太多**：把视频、整幅点云不停往上灌，网络一差就卡死，边侧也拼不出稳定可用的「世界」。
2. **控太死或不安全**：模型直接下发底层速度指令，或只看图像/模型内部黑盒状态，和端侧真实地图对不上号；命令过期了还在执行，容易时空错位。
3. **地图太扁**：现有实现多把传感器数据压成**单一平面/单层地图模型**，而机器人感知与任务需要几何、语义、位姿等**多维**信息；缺少能按层组织、增量维护多维地图的**端侧分层空间地图数据管理库**，也就难给重建、世界模型、规划等不同消费者按需供数。

我们要做的是：

> **机器人端侧用增量分层地图库把「变化了的局部世界」按层打包上传 → 边侧按需拼好（重建可全吃、模型可按需，资产也可喂模型）→ 模型出任务级动作/轨迹 → 机器人核对接命令是否过期后本地安全执行 → 结果再写回世界。**

### 1.2 本发明主要解决的技术问题（归纳）

1. 在线建图输出难以被边侧动作模型稳定、可版本地消费；全量上图带宽不可持续。
2. 几何、语义、位姿等空间信息混在一起时，无法在弱网下按重要性取舍，也无法给渲染/规划/模型不同订阅。
3. 现有方案常把传感数据收敛为单一平面/单层地图，缺少端侧增量分层的多维地图数据管理库，难以同时支撑三维重建（全量消费）、世界模型（按需消费）与本地规划等差异化需求。
4. 边侧若只有单层稀疏摘要，动作模型缺少可拼接的结构化世界输入；若要求端侧每次灌全图，又不现实。
5. 语义/动作模型与端侧执行缺乏统一的空间版本与时效约束，断连时难以安全降级，失败难以归因。



### 1.3 发明目的

提供一种**不绑定某一 SLAM 框架、不绑定某一大模型权重**的端边协同方法与系统，实现：

1. 端侧维护**增量分层空间地图数据管理库**（→ **C-a**），将局部世界按**分地图层**做成**版本化局部增量包**（→ **C-b LayerDelta**）并上传（默认不是每次全场全量）；
2. 边侧默认吃增量，任务需要时**按需补层/补区**，在任务窗口内拼出「够用的逻辑全量」地图视图；
3. 世界动作模型（或视觉-语言导航/动作模型经适配）以该**契约化拼接地图视图**为条件生成**结构化动作组**；
4. 动作组携带来源空间版本与存活时限，端侧校验后由**本地规划 + 安全接口**执行，模型不作为底层速度唯一来源；
5. 执行终态回写世界，形成可重放闭环；
6. （优选）带宽受限时优先保障空间主层增量与版本连续。



### 1.4 相对现有技术的优点（写效果时用「可实现/有助于」，定量待测）

## 2. 技术背景与最相近的已有方案



### 2.1 技术背景（领域常识）

机器人同步定位与建图（SLAM，Simultaneous Localization and Mapping）解决「我在哪、周围几何长什么样」。  
边缘计算把重计算放在边侧服务器。  
视觉-语言导航（VLN，Vision-Language Navigation）/ 视觉-语言-动作（VLA）/ 世界动作模型（WAM，World-Action Model）根据观察与任务意图生成动作。  
行业无人机「上云 API」常用任务分层：全局策略、航线/子任务、触发式动作组；资源目录里常放媒体文件。

### 3.1 系统总体：谁连谁（结构/原理框图）

**图 1　系统总体连接关系图（原理框图）**

```text
┌─────────────────────────────┐         通信链路(500)        ┌──────────────────────────────┐
│ 端侧装置(100)                 │◄────── 上行：分层增量包 ──────►│ 边侧系统                      │
│ 传感器(110)→建图(120)         │─────── 下行：动作组 ─────────►│ 契约与编排装置(200)            │
│ →事务与分层封装(130)→发送(140) │◄────── 补传请求/校正 ────────│ 世界拼接装置(300)              │
│ 接收校验(150)→本地规划(160)   │─────── 终态回传 ─────────────►│ 动作模型装置(400)              │
│ →安全接口(170)→执行机构(180)  │                              │                              │
└─────────────────────────────┘                              └──────────────────────────────┘
```

**图 1 文字说明：**  

- **端侧装置（100）**：装在机器人上。传感器（110）提供激光点云、惯性测量单元（IMU，Inertial Measurement Unit）数据等；在线建图模块（120）输出位姿与增量空间状态；事务与分地图层封装模块（130）打版本、按层打包；发送模块（140）上行；接收校验模块（150）收下行动作组并查版本/时效；本地规划模块（160）生成可执行轨迹；安全接口模块（170）做碰撞/急停兜底；执行机构（180）为电机/足式控制接口。  
- **通信链路（500）**：可为无线局域网、蜂窝网络等，本发明不限定物理层。  
- **边侧**：契约与编排装置（200）管握手与任务组装；世界拼接装置（300）管增量合并与按需补全；动作模型装置（400）根据拼接地图视图生成动作组。三装置可合在一台服务器，也可分进程，逻辑上分离即可。

**各模块在本发明中的作用：**  
端侧保证「实时感知、可安全执行」；边侧保证「记得住、拼得够、想得清」；链路只传契约对象，不要求传原始视频主流。

### 3.3 分地图层与数据包结构（结构特征图）

**图 3　分地图层与空间数据包结构示意图**

```text
空间数据包 / LayerDelta（示例容器，字段名可替换；正式 C-b 见交底书）
├── 信封 envelope
│     delta_id、base_version_hash、target_version_hash（内容寻址版本）
│     session、time、changed_layers、affected_layers、coord_anchor
├── affected_layer_entries[]   # 层条目（layer_id / region / change_type / payload_ref …）
│     layer_geometry  几何层：点云块 / 哈希体素增量 / 可选距离场补丁
│     layer_semantic  空间语义层：标签、对象摘要等（可缺省）
│     layer_state     位姿与状态层：关键位姿、位姿图边、定位置信等
└── （可选）deps[] / confidence / MERGE 变更类型 → C-b 从属
```

**图 3 文字说明：**  

- **LayerDelta / 空间数据包**：C-b 核心保护对象；版本挂**不可变 DAG**，组合语义为 `compose(base, deltas[]) → new_version`（纯函数）。  
- **几何层**：描述障碍与可通行几何，供规划/碰撞与模型空间条件使用；表达可以是哈希体素、点云块或网格，**不绑死某一种**。  
- **空间语义层**：描述「这是什么/哪一类区域」，供任务理解；可无则包可变瘦。  
- **位姿/状态层**：描述机器人在世界中的位姿与相关状态，供时间对齐与重定位。  
- **清单**：让接收端知道如何合并、缺哪层、版本是否连续。  
- **作用**：把「世界」拆成可独立传输与订阅的层；借鉴行业任务包「元数据/执行/资源分目录」的**思想**，资源目录改为地图层，**不复制**某一厂商航线文件的字段名与目录名。

**对象分层（防止权要写窄）见图 3 右侧逻辑：**

```text
空间事务（事实）→ LayerDelta / 分地图层增量 → 版本 DAG + compose（C-b）
  → 网络载荷（传输实现）→ 按 AccessTicket 物化视图（C-c）→ 模型输入（适配器派生，C-d/e）
```

独权宜钉前几层组织方式；具体文件名、库名进实施例。

### 3.5 边侧按需补全与多消费者（原理框图）

**图 5　边侧汇聚、按需补全与分层消费图**

```text
上行增量包 → 合并器 → 局部/区域视图缓存
                ↓ 缺口？(任务包围盒未覆盖 / 缺层 / 模型 RequestFill)
           是 → 补传请求 → 端侧或历史库 → 再融合 → 任务窗口「逻辑全量」拼接视图
                ↓
        ┌───────┼────────┐
        ↓       ↓        ↓
     三维重建/渲染    动作/大模型      全局一致性       本地执行
     (主:几何层)     (主:几何+语义)   (主:位姿/状态层)  (局部几何+位姿)
```

**图 5 文字说明：**  

- **默认路径**：只吃增量，边侧可以暂时很稀疏——这符合发明人现状（边侧曾很稀），也正是本方案要解决的。  
- **按需补全**：不是「端侧永远传全世界」，而是「任务需要哪块/哪层再要」。  
- **多消费者默认映射（优选，非独权一对一）**：动作/大模型主订几何+语义（位姿对齐）；三维重建/渲染主订几何；全局一致性主订位姿/状态层；本地执行订局部几何+当前位姿。  
- **AccessTicket（→ C-c 卫星）**：消费者持令牌声明 allowed_layers / allowed_regions / version_cap /（可选）qos；边侧 **lazy materialization** 后投影下发——**不是**电子地图购图鉴权令牌。  
- **作用**：打通「传得少」与「各消费者用得够」。

### 3.6 任务下行结构（结构图）

**图 6　下行任务分层结构图（借鉴思想，自有语义）**

```text
MissionConfig 全局任务策略
  （失控/断链/超时怎么处理、速度上界、能力约束）
  └── Subtask / Folder 子任务路径（去哪些点/区域）
        ├── startActionGroup 开始前动作（可选）
        └── ActionGroup 动作组
              ├── 生效区间（哪段路径）
              ├── 触发条件（到达点 / 路径中 / 时间 / 距离等）
              ├── 有序动作列表（前往、朝向偏好、等待、采集、技能名…）
              └── source_space_version + time + TTL
```

**图 6 文字说明：**  

- **ActionGroup（动作组）**：结构化任务指令集合，不是轮速。  
- **source_space_version**：生成该动作时所依据的空间版本；端侧用来判断「地图是否已变」。  
- **TTL**：超过存活时间则视为过期。  
- **作用**：把「怎么走」和「走到了干什么」分开表达；与上行空间包成对，构成完整交互面。  
- 名称 Folder/ActionGroup 可换成 Subtask/ActionSet，避免与航空厂商格式混淆。

### 3.7 版本校验与安全降级（流程图）

**图 7　端侧接纳校验与安全降级流程图**

```text
收到下行动作组
  → 契约版本兼容？否 → 拒绝，回传错误
  → source_space_version 连续且未过旧？否 → 拒绝或请求基于最新拼接视图重生成
  → 未超过 TTL？否 → 拒绝，目标过期
  → 本地安全态允许（未急停、定位可用）？否 → 挂起语义任务，维持安全行为
  → 全部通过 → 本地规划生成轨迹 → 安全接口限速/避碰/急停 → 执行
通信失败或模型不可用 → 进入降级：本地避障/静止/按失控策略动作；缓存关键上行，恢复后补传
```

**图 7 文字说明：**  
底层速度由本地规划与安全接口产生；动作模型**不是**唯一底层控制源。  
降级的作用：弱网、断连、模型超时情况下，机器人仍能「活着」，并在恢复后把迟到的增量交给边侧插入版本链。

## 4. 关键点与欲保护点



### 4.1 关键点（发明点，用人话）

1. **把局部世界按层做成带版本的增量包再上传**，默认不灌全图。

## 5. 替代方案（同样能完成发明目的）

在不脱离本发明主旨前提下，下列替代均可：

1. **几何表达**：哈希体素 / 八叉树 / 点云块 / 网格 / 距离场补丁互换。
2. **层集合**：可增加拓扑层；语义层可缺省；层数不固定为三。
3. **触发逻辑**：运动与空间变化「或/与/加权」；可加任务事件、定时心跳。
4. **封装格式**：Protobuf、FlatBuffers、自定义二进制、ZIP 类归档等。
5. **动作模型**：WAM、VLA、VLN、规则+大模型混合；只要输出结构化动作组并经适配。
6. **任务表达**：行为树子树、状态机、任务图等价于 Subtask+ActionGroup。
7. **补全触发**：规则判定、模型显式请求、人工标注区域。
8. **规划与安全**：采样式/优化式/学习式局部规划；厂商 SDK 或独立安全层。
9. **通信**：直连、网关中转、存储转发；断连缓存后批量补传。
10. **「逻辑全量」窗口**：空间包围盒、时间窗或拓扑子图。

### 6.3 一个完整实施例故事（代理人可改写进说明书）

足式机器人搭载激光与惯性器件，机载运行在线建图。行走中当位移或地图变化达到条件时，把几何层增量与位姿层打进空间数据包，经无线网上传至机房 x86 服务器。服务器合并后发现当前巡检任务区域缺语义层，下发补传请求；机器人补传语义增量。服务器拼出任务区视图，视觉-语言导航模型（顶替 WAM）输出「前往 A 点并保持朝向」的动作组，携带空间版本与 3 秒级 TTL。机器人发现版本仍匹配，交本地导航执行；途中急停接口保持有效。到达后回传成功终态与版本号。若中途断网，机器人本地避障等待，缓存关键包，恢复后补传并由服务器按版本插入。
