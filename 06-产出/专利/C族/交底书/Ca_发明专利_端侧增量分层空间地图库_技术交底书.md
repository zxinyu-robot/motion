## 1、本发明要解决的技术问题、目的；与现有技术相比的优点

### 1.1 要解决的技术问题

机器人综合规划（通行、避障、跨高度/多层平面任务等）往往需要在**三维多层平面**上联合利用几何可通行性、位姿状态及可选语义等信息。但现场常用的传感与建图流水线，各自输出的是**局部、低维、面向单一环节**的数据结构，例如：

- 定位建图前端：位姿流 + 面向匹配的紧凑内部图；  
- 旁路几何：去畸变点云、局部体素/块；  
- 可选语义：图像/点云标签、对象摘要；  
- 规划侧习惯输入：局部 2D 占据或单层 costmap。

问题不在于「现有技术没有多层地图」，而在于资源受限端侧缺少一种**增量组合机制**：把上述已有流水线产出的原材料，高效汇入同一份**可版本对齐、可分层取用、可供规划与模型消费**的多维结构；否则下游只能各自另起炉灶，或被迫在局部低维视图上做「综合规划」，维度不足且版本难对齐。

### 1.2 发明目的

提供一种端侧方法、装置及系统，使其：

（1）**不重做**各传感/建图流水线本身，而以各流水线既有输出结构为原材料；  
（2）以**增量**方式把原材料按层路由写入一份独立的分层空间地图库（主源层优先，增强层可选）；  
（3）输出一份统一会话/空间版本下的**多维可消费结构**，供本地三维多层综合规划投影，并可供动作/世界模型等按层取用（完整端边交互另案）；  
（4）前端内部匹配图不作为默认对外世界图；几何以旁路方式进入几何层。

### 1.3 与现有技术相比的优点


| 优点     | 说明                               |
| ------ | -------------------------------- |
| 对接综合规划 | 面向三维多层平面综合规划，而不是停在局部单层低维出口       |
| 增量组合   | 复用既有流水线输出，增量汇入，避免全量重算与互不版本对齐的多套库 |
| 层次清晰   | 主源（几何+位姿）可独立支撑规划；语义等增强可后置        |
| 可模型消费  | 同一多维结构可投影给规划，亦可按层供模型取用           |

## 2、技术背景与最相近实现方案

### 2.1 技术背景

足式/轮式等机器人在室内外、坡道与多层空间作业时，综合规划需要三维几何与多层平面信息。现有传感—建图—规划链路中，各环节优化目标不同：前端求定位稳、规划求局部可行、语义求标签准，出口常为局部低维。场景图、GIS 图层、城市 CIM 等亦有「多层/投影」思想，但与**机器人端侧在线、以既有建图流水线输出为原材料、增量组成可规划/可模型消费结构**的约束不同。

### 2.2 最相近方案及缺点（发明人摸底，请代理人检索核实）

**（1）紧耦合 LIO + 内部紧凑匹配图**  
相近：实时位姿与局部几何。缺点：出口服务匹配；不宜直接充当三维多层综合规划与模型消费的统一结构。

**（2）单层/局部占据规划图（2D costmap、局部 BEV 等）**  
相近：可直接喂规划器。缺点：维度塌到局部低维平面，难支撑跨高度/多层平面的综合规划信息组织。

**（3）语义 SLAM / 多层语义或场景图系统**  
相近：几何上叠语义或拓扑。缺点：常与特定前端/整包算法绑死；端侧算力下难以及时满负荷；未必以「增量组合既有流水线出口 + 统一空间版本」为组织目标。

**（4）GIS/CIM/LOD 多图层发布**  
相近：按消费者投影、图层独立。缺点：偏离线/平台侧汇聚，不是机器人端侧对在线建图流水线输出的增量组合库。

### 2.3 本发明差异（请勿滥用「首次」）

本案不主张「发明了分层地图」本身，而主张：在机器人端侧，以各传感建图流水线的既有数据结构为原材料，**增量组合**为一份带主源/增强层次与会话空间版本的多维结构，并据此投影支撑三维多层综合规划及可选的模型消费。完整端边动作闭环不作为本案必选独权特征。

## 3、技术方案详细阐述（结合附图）

### 3.1 发明要点与层次（图 1 为实施环境示意）

图1 端侧分层地图库总体结构图

图 1 仅说明实施环境：传感/建图流水线、规划器、可选模型等均属**既有或可替换部件**，**不是**本发明的区别技术特征。本发明是一套**增量组合与组织方法**，回答三件事：

1. **用什么**：各流水线已输出的局部数据结构（位姿流、旁路几何观测、可选标签等）作为原材料；不把前端内部匹配图当作可消费世界图。
2. **怎么组**：按主源/增强层次路由增量写入，经统一空间索引关联，并打上会话与空间版本。
3. **产出什么**：一份可供三维多层综合规划投影、并可按层供模型取用的多维结构（完整端边交互另案）。

**层次重点（主次，此为组织规则）：**


| 优先级   | 层      | 组织规则                            |
| ----- | ------ | ------------------------------- |
| P0 主源 | 几何层    | 必须维护；承载三维可通行/障碍，可投影到多层平面或局部规划视图 |
| P0 主源 | 位姿/状态层 | 必须维护；提供综合规划的时空基准与对齐             |
| P1 增强 | 空间语义层  | 可缺省；标签经空间索引挂到几何单元，不阻塞 P0 规划     |
| P2 扩展 | 拓扑等    | 可增减；不进本案独权必选                    |


组织原则：**先保证 P0 可规划，再按需挂 P1/P2**；增量组合，不替换各流水线内部算法。

### 3.2 增量组合方法步骤（图 2）

图2 分层地图库管理流程图

**S1 定层与主次**：在端侧维护分层组织：至少几何层、位姿/状态层；可选语义层；约定统一空间索引。  
**S2 收原材料**：接入各流水线输出的分类型结构，校验会话、坐标系等契约。  
**S3 按层增量组合**：位姿写入位姿/状态层；旁路几何写入几何层（表达可替换）；可选标签写入语义层（可跳过）。  
**S4 版本提交**：单调更新会话与空间版本，记录本周期变更层；任一流水线内部缓存淘汰不得直接解释为现实障碍消失。  
**S5 规划/模型取用**：由几何层与当前位姿投影生成多层平面或局部占据等综合规划视图；并允许按层查询供模型消费。  
**S6（可选）局部增量导出**：按触发条件导出版本化分层局部增量。

## 4、关键点与欲保护点

### 4.1 关键创新点（关键词）

不是新增传感器或再建一个 SLAM；而是：以既有流水线局部低维出口为原材料 → 按主源/增强层次增量组合 → 统一空间版本 → 投影给三维多层综合规划，并可按层供模型消费。

### 4.2 建议独立权利要求方向

一种面向三维多层综合规划的端侧增量分层空间地图组织方法，其特征在于包括：获取各传感与建图流水线输出的分类型数据结构作为原材料；按主源层与可选增强层将所述原材料增量组合为统一空间索引关联的多维分层结构，所述主源层至少包括几何层与位姿/状态层；维护会话与空间版本；根据所述几何层与当前位姿投影生成供三维多层综合规划使用的视图；可选地按层提供供模型消费的数据取用或局部增量导出。

装置/系统独权：以实现上述组织方法的功能单元表述，**勿**将传感器、定位建图前端等既有部件写成区别特征。

### 4.3 建议从属方向

（1）几何层表达可替换（哈希体素、点云块、栅格块等）；  
（2）语义层可缺省，不阻塞主源规划；  
（3）规划投影包括多层平面视图、局部三维占据或降维 2D 视图之一或其组合；  
（4）前端内部匹配图不作为默认世界图，几何旁路灌入；  
（5）缓存淘汰不解释为现实障碍消失；  
（6）按运动和/或几何变化触发导出分层局部增量。

### 4.4 请勿写入独立权利要求硬约束

- 传感器种类清单、某一开源 LIO/规划器/语义网络/场景图名称；  
- 将「传感器模块 / 前端模块 / 导出模块」等常规部件本身当作区别特征；  
- 「必须端侧实时跑满语义大模型或三维高斯重建」；  
- 完整弱网 QoS、世界模型冲突融合、动作闭环（另案/后续）；  
- GIS/CIM 平台产品名称；未实测数字；具体数据库产品类型。
