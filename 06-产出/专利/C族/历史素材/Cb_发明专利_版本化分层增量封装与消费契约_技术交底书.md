## 1、本发明要解决的技术问题、目的；与现有技术相比的优点



### 1.1 要解决的技术问题

端侧（或等价生产者）已能维护一份**分地图层、可版本对齐**的空间状态（见 C-a 或同类库），供本地规划投影。但当需要把空间状态交给边侧/云侧模型、多消费者或远端规划器时，现有做法常落入下列断层：

1. **传输组织断层**：全量上送点云/整图带宽不可持续；仅传图像或不可解释特征，则边侧无法与端侧共享同一空间版本语义。
2. **增量语义断层**：通用电子地图差分、瓦片/图层补丁多面向导航电子图或 HD Map 产品；对机器人侧「几何主源 + 可选语义/位姿层、旁路灌入、缓存淘汰≠现实清除」的契约语义覆盖不足。
3. **消费契约断层**：既有「令牌 + 瓦片」多为**商业购买范围鉴权**；缺少面向技术消费的契约——消费者声明可取层、空间范围、可消费最高版本后，服务端再**按契约选择性物化**视图，而非默认甩整库。
4. **组合/回滚断层**：仅有单调版本号递增时，难表达「在某一基版本上应用若干分层局部增量得到目标版本」的可回放组合；版本不连续时的拒收/重取语义不清晰。

问题不在于「世界上没有地图差分」，而在于缺少一种面向机器人端边协同的中间层：**把分地图层局部变化封成带版本组合语义的增量信封，再按消费者契约投影下发**。

### 1.2 发明目的

提供一种方法、装置及系统，使其：

（1）以端侧（或等价）**版本化分层空间状态**为输入原材料，不重做 SLAM/分层库内部算法；  
（2）按触发条件抽取关键时空切片，将变化组织为**分层局部增量包**（信封 + 载荷引用/载荷）；  
（3）信封显式携带会话、基版本/目标版本（或等价版本区间）、受影响层、坐标锚点及生产者校验信息，使应用过程可视为可回放组合；  
（4）支持消费者以**消费契约令牌**声明允许层、允许区域、版本上限等，服务端（或边侧分发节点）据此**选择性物化**投影视图后下发；  
（5）完整动作模型闭环、弱网细调度、多机写冲突仲裁**不作为本案必选独权特征**（另案）。

### 1.3 与现有技术相比的优点


| 优点     | 说明                                 |
| ------ | ---------------------------------- |
| 默认局部增量 | 按层、按区域传变化，避免每次全场全量                 |
| 版本可组合  | 基版本→目标版本语义清晰，便于拒收、重取、回放            |
| 层可独立取舍 | 几何主源优先；语义等增强层可缺省或后补                |
| 契约驱动投影 | 令牌声明技术消费范围，按需物化，区别于单纯购图鉴权          |
| 与上下游解耦 | 输入可接 C-a 类库；输出可接拼接/模型案；前端与序列化格式可替换 |

## 2、技术背景与最相近实现方案



### 2.1 技术背景

足式/轮式机器人端边协同中，机载侧重定位建图、本地规划与安全；边侧/云侧侧重语义理解、任务规划或多人机汇聚。中间需要可版本对齐的空间数据通道。学术上有 Map API、场景图增量、多机协同建图等；产业上有导航电子地图差分、车路协同高精地图分层分发、购图鉴权瓦片下发等。本案聚焦**机器人分地图层局部增量的封装契约 + 消费投影契约**。

### 2.2 最相近方案及缺点（发明人摸底，请代理人检索核实）

**（1）导航电子地图 / HD Map 差分与瓦片更新**  
相近：差分包、多版本比对、按区域/瓦片更新（如早期 PSF 差分类、NNG 等 tile×layer delta + 版本确认类公开案）。  
缺点：产品语境多为车载导航电子图；未必绑定机器人旁路几何主源、分地图层独立取舍、以及「缓存淘汰≠障碍消失」等 Producer 语义；组合对象常为瓦片产品而非端侧 SLAM 旁路库的局部增量信封。

**（2）高德类「购买范围令牌 + 地图瓦片下发」**  
相近：用户端授权→令牌→带令牌请求→校验后下发瓦片。  
缺点：令牌核心是**商业购买/授权范围**，不是「allowed_layers / allowed_regions / version_cap」驱动的**技术订阅与按契约物化**；与机器人在线增量流、会话空间版本闭环不同。

**（3）分层地图库内的按层选择性更新（如南湖七层类）**  
相近：多信息层、对齐世界系、按触发选择性更新再整合。  
缺点：解决的是**库内表示与更新**（更近 C-a）；未解决跨端「增量信封封装 + 消费契约分发」。本案不主张「发明了分层地图」。

**（4）通用 RPC / 消息中间件传任意字节流**  
相近：可传输任意载荷。  
缺点：不规定何时抽切片、如何按层封装、如何按契约投影、如何做版本组合拒收。

**（5）仅传视觉特征 / 神经参数更新的边缘 SLAM**  
相近：省带宽的端边协同。  
缺点：载荷多为不可解释特征，边侧难以按层拼接为可规划/可模型消费的结构化世界视图。

### 2.3 本发明差异（请勿滥用「首次」）

本案不主张：分层地图结构本身、通用地图差分机制本身、购图鉴权令牌本身、某一 content-hash/Merkle 算法本身。

本案主张：在机器人端边（或端—分发节点）场景下，将版本化分地图层状态的**局部变化**封装为带**版本组合语义**的分层增量信封，并可选地以**消费契约令牌**驱动按层/按区/按版本上限的选择性物化与下发。完整字段名与伪码申请前勿对外公开。

## 3、技术方案详细阐述（结合附图）

### 3.1 发明要点（图 1 为实施环境示意）

图1 版本化分层增量封装与消费分发总体结构图

图 1 仅说明实施环境：在线建图前端、分层地图库、通信链路、边侧模型/规划器等均属**既有或可替换部件**，不是区别技术特征。本发明是一套**封装与分发组织方法**，回答三件事：

1. **封什么**：来自版本化分层空间状态的局部变化（按层、按区域），而非默认整库。
2. **怎么封**：增量包 = **信封（envelope）+ 载荷引用/载荷（payload）**；信封承载版本组合与受影响层等契约元数据。
3. **怎么给**：消费者持**消费契约令牌**；分发侧按令牌声明做**选择性物化**后下发投影视图或对应增量子集。

**与 C-a 的边界**：C-a 负责端侧「增量组合进库」；C-b 负责「出库封装与按契约分发」。二者可同日申请，独权勿互相吞并。

### 3.2 方法步骤（图 2）

图2 分层增量封装与契约分发流程图

**S1 接入版本化分层状态**  
获取生产者侧当前会话下的分地图层空间状态或其变更流（几何层、位姿/状态层为优选主源；语义等为可选增强）。状态来源可以是 C-a 类分层库，也可以是等价 Producer。

**S2 判定关键时空切片（优选）**  
以运动变化条件和/或空间（几何）变化条件联合判定是否形成关键切片；可选任务变更或超时兜底。阈值仅实施例，不写死独权。

**S3 组装分层局部增量包**  
对关键切片，按层提取局部变化，生成增量包：

- **信封**：至少包括会话标识、基版本标识、目标版本标识（或等价版本区间）、受影响层列表、坐标锚点、时间信息；优选含生产者校验信息（签名或完整性摘要之一）。  
- **层条目**：每一受影响层包括层标识、空间范围（如区域框/瓦片集/索引集合之上位）、变更类型、载荷引用或内联载荷；可选置信度、依赖列表（用于乱序到达时重组）。  
- **变更类型（优选集合）**：至少区分新增、更新、缓存淘汰、会话重置；可选合并类变更。其中**缓存淘汰不得解释为现实障碍消失**。

**S4 发布或上行**  
将增量包经通信链路发送至边侧分发节点、模型节点或版本化存储；网络序列化格式可替换（结构化二进制、归档容器等），属从属/实施例。

**S5 消费契约令牌（可选但优选写入从属或第二独权）**  
消费者或调度器出示令牌，令牌技术声明至少包括：允许的地图层集合、允许的空间区域约束、可消费的最高版本（version_cap）中的一项或多项；可选服务质量等级（如至多一次/至少一次等之上位表述）。  
**【划界】** 该令牌是**空间数据消费契约**，不是电子地图商品购买凭证。

**S6 按契约选择性物化**  
分发侧根据令牌与当前版本化分层存储，物化对应投影视图或增量子集并下发；未授权层/区域不物化；超过 version_cap 的版本不提供或仅提供截止版本。

**S7 版本组合与拒收语义**  
接收方（或存储侧）按「在基版本上应用增量得到目标版本」的语义组合；基版本不匹配或版本不连续时拒收、请求补基版本或重取；回滚可通过切换当前版本指针实现（具体存储结构可替换；Merkle/content-hash 仅优选实施例，**不宜作为唯一区别特征**）。

**（接口预留，不进本案必选独权）** 边侧模型基于物化视图生成粗粒度目标/动作组、端侧校验执行与终态回写——见 C-e/f 等另案。

### 3.5 使用案例（实施例，开源/产品名不进独权）

**案例 A：单机端边上行几何主源（主案例）**  
足式机器人端侧维护几何层 + 位姿层。位移或几何变化触发后，封装仅含几何与位姿层条目的局部增量包上行至机旁计算节点；节点按版本链组合，供后续模型或规划读取。语义进程关闭时，affected_layers 不含语义层。

**案例 B：契约驱动的多消费者投影**  
同一版本化存储上，本地规划消费者令牌仅允许几何层 + 机器人周围局部区域；边侧语义模型消费者令牌允许几何层 + 语义层、任务廊道区域、version_cap 绑定当前任务会话。分发侧对两枚令牌分别物化，互不强迫对方接收整库。

**案例 C：版本不连续拒收**  
边侧因丢包缺少某一基版本，收到 target 不连续的增量包后拒收并请求补传基版本或关键区间，避免静默错拼。

**案例 D（从属）：带宽降级保主层**  
链路劣化时优先封装并发送几何层 + 位姿层及版本元数据，暂缓语义层——仅体现优先保主层与版本连续；完整弱网 QoS 见 A4/论文，不抢本案独权。

具体机型、开源 LIO、消息中间件、序列化库名称仅实施例。

## 4、关键点与欲保护点

### 4.1 关键创新点（关键词）

把机器人侧版本化分地图层状态的**局部变化**，封装为带**基版本→目标版本组合语义**的分层增量信封；并可选地用**消费契约令牌**驱动按层/按区/按版本上限的选择性物化下发——不是再发明一种分层地图，也不是电子地图购图鉴权。

### 4.2 建议独立权利要求方向

**独权一（封装方法，推荐主独权）**  
一种机器人空间数据增量封装方法，其特征在于包括：获取版本化分地图层空间状态或其变更；按触发条件确定关键时空切片；将所述切片中的局部变化封装为增量包，所述增量包包括信封和至少一层条目，所述信封包含会话标识、基版本标识、目标版本标识、受影响层信息与坐标锚点，所述层条目包含层标识、空间范围、变更类型以及载荷或载荷引用；将所述增量包发送或写入可被下游消费的通道或存储。

**独权二（契约分发方法，可并案或第二独权）**  
一种基于消费契约的地图数据分发方法，其特征在于包括：维护或接收版本化分地图层存储及分层局部增量；获取消费者令牌，所述令牌包含允许层集合、空间区域约束、可消费最高版本中的至少一项；根据所述令牌从所述存储或增量中选择性物化投影视图或增量子集并下发。

**装置/系统独权**：以实现上述方法的功能单元表述；勿将传感器、某一 SLAM 前端、某一模型写成区别特征。

### 4.3 建议从属方向

（1）变更类型至少包括新增、更新、缓存淘汰、会话重置；缓存淘汰不解释为现实障碍消失；  
（2）关键切片由运动变化与空间变化联合触发，和/或任务变更/超时兜底；  
（3）层条目含依赖列表，支持乱序重组；  
（4）信封含生产者完整性校验；  
（5）几何层为默认主源层，语义层可缺省；  
（6）令牌进一步包含投递服务质量等级声明；  
（7）基版本不匹配时拒收并请求补基版本或重取；  
（8）回滚通过切换当前版本指针实现；版本标识可采用单调序号和/或内容摘要（摘要为优选而非唯一）；  
（9）带宽受限时优先传输主源层与版本元数据；  
（10）增量包与网络载荷分离，载荷格式可替换。

### 4.4 请勿写入独立权利要求硬约束

- 「发明了分层地图 / 七层信息层结构」；  
- 「通用电子地图差分 / 瓦片兼容表」单独作为唯一特征；  
- 「购买商品地图的鉴权令牌」流程复制；  
- content-hash / Merkle 树作为**唯一**区别特征；  
- 必须端侧实时跑满语义大模型或三维高斯重建；  
- 完整世界动作模型（WAM）动作闭环、弱网 QoS 矩阵、多机冲突仲裁；  
- 某一开源 LIO/中间件/序列化库/数据库产品名称；  
- 未实测的带宽/成功率数字；完整字段定稿伪码。

## 5、替代方案

（1）触发条件可仅为运动、仅为几何变化、或周期触发；  
（2）载荷可内联或外置对象存储 + payload_ref；  
（3）版本标识可采用单调计数、向量时钟或摘要链之一或其组合；  
（4）消费契约可与传输信道绑定的会话能力协商合并实现，而不单独签发令牌文件；  
（5）物化可在端侧完成后再发「已投影子集」，或在边侧分发节点完成；  
（6）无语义层时仅几何+位姿两层即可支撑案例 A；  
（7）封装模块可与分层库同进程或独立进程。
