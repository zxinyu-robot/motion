## 一、建议专利名称

一种基于空间数据流契约的机器人与世界动作模型交互方法、装置及系统

备选名称（供代理人择一）：

1. 一种版本绑定的分层地图拼接视图条件动作生成与边端安全执行方法  
2. 一种边侧按需补全的局部世界增量交互与动作组闭环方法  

---

## 二、技术领域

本发明涉及机器人中间件、空间数据接口、世界模型、视觉-语言-动作 / 世界动作模型、任务编排、边缘计算以及机器人本地规划与安全控制技术领域，尤其涉及一种通过可协商的空间数据与任务契约，使机器人按分地图层发布版本化局部世界增量，使边侧在增量基础上按需补全并拼接任务相关地图视图，使世界动作模型（或等价语义动作模型）以该契约化拼接视图为条件生成结构化动作组，经任务编排层下发并由边端在版本与安全校验后执行、再将执行终态回写世界状态的交互方法、装置及系统。

---

## 三、背景技术

具身机器人与远程/边缘智能体协同时，业界常见两类接口形态：

1. **无人机/机器人上云任务 API**：以物模型状态上报、媒体回传与航线/动作组（如路径 Folder + 触发式 ActionGroup）完成任务编排，擅长「任务怎么走、到了干什么」，但上行资源槽多为媒体或战术标注，**不以分地图层版本化局部世界增量作为模型条件输入的主契约**，也难以把执行失败归因到具体空间版本。  
2. **端到端视觉-语言-动作模型**：以图像/视频或**模型私有隐状态**直接生成控制，交互简单，但边端与模型侧往往不共享可查询、可回放、可拼接的结构化世界版本；网络时延下易时空错位；模型直出底层速度时安全边界不清。

工程上还常见：端侧建图已可用，但边侧仅收到**单层稀疏**摘要，无法支撑上层动作模型；或每次要求端侧灌送全局全量地图，带宽不可持续。

因此，需要一种不绑定具体云厂商协议字段、不绑定具体动作模型权重的交互方法，其交互载体明确为：**分地图层增量空间 Token（或等价数据包）上行 + 结构化 ActionGroup 下行**，并由边侧完成按需补全与拼接后供模型消费。

---

## 四、发明目的

1. 边端与智能体侧通过**可协商契约版本**对齐空间对象与任务对象语义；  
2. 机器人按**分地图层**发布版本化**局部**世界增量（默认非全局全量）；  
3. 边侧默认维护增量局部视图，并在任务需要时**按需请求补传或融合历史层**，在任务窗口内拼接为「逻辑全量」地图视图；  
4. 世界动作模型消费该**契约化拼接地图视图**（绑定空间版本），而非仅私有隐状态；输出结构化动作组/子任务，不直接作为底层速度唯一来源；  
5. 任务编排层组织全局策略 / 子任务 / 动作组，并携带 source_space_version 与 TTL；  
6. 边端校验后本地安全执行；异常时降级；终态回写世界；  
7. （从属）带宽受限时优先保空间主层与版本连续——细调度见论文/A4。

**【设计决策】** 「几何世界为底座」可作为产品/论文表述与优选实施方式（几何层优选为主层），**不得**写成「非几何约束世界模型即不落入保护范围」的独权硬约束。

### 5.0 交互主链（本案脊柱）

```text
端侧：分地图层局部增量 Token/数据包 ↑
        → 边侧：默认吃增量局部视图
        → 任务需要时：按需补层/补区/融合历史 → 任务窗口内「逻辑全量」拼接视图
        → WAM：消费契约化拼接地图视图（非私有隐状态）+ 任务意图
        → ActionGroup（及可选 Subtask）↓（绑定 source_space_version / TTL）
        → 端侧：版本与安全校验 → 本地规划执行
        → 终态回写世界 → 下一轮
```

通信链路上各层配额随链路质量调整的细节：**优选实施方式 / 论文**；专利仅保留从属一句（§5.8）。

### 5.1 方法总体流程

```text
T1  契约协商：能力声明与契约版本（空间层集合、任务对象、坐标系、最大时滞等）
T2  世界上行：边端按契约发布分地图层版本化局部增量
    （session、space_version、changed_layers、各层 spatial_delta；
     默认局部增量，非每次全局全量；图像辅通道可选）
T3  边侧汇聚与按需补全：
    T3a 默认：将增量合并进可查询局部/区域视图；
    T3b 当任务 ROI、覆盖缺口或模型请求需要时：
        向端侧或历史库请求补传指定层/区域，或融合历史层，
        在任务时空窗口内拼接为逻辑全量地图视图
T4  条件构造：取出绑定指定 space_version（或版本区间）的拼接地图视图
T5  动作生成：世界动作模型以该拼接视图 + 任务意图为条件，
    生成 ActionGroup 和/或 Subtask（非底层速度）
T6  任务编排：Mission 策略 + Subtask/Folder + ActionGroup；
    强制携带 source_space_version、time、可选 TTL
T7  边端接纳：契约兼容、版本连续/未过期、安全态允许 → 本地规划执行
T8  安全降级：断链/过期/模型不可用 → 拒绝或挂起语义动作，本地安全链独立运行
T9  结果回写：终态、失败码、关联 space_version → 更新世界，供下一轮 T3–T5
```

### 5.2 空间数据流契约（可协商，不绑死字段名）

| 对象类 | 最小语义（上位） | 说明 |
|---|---|---|
| 空间发布对象 | session、space_version、time、changed_layers、按层 spatial_delta | 对齐 C0 Token/分地图层数据包；格式可替换 |
| 任务下行对象 | mission、subtask/Folder、ActionGroup、source_space_version、TTL | 借鉴行业任务分层思想；**不复制**厂商 WPML/KMZ 字段 |

**【设计决策】**  

- 独权钉契约语义与交互步骤，不钉产品名、开源项目名、REST 路径字符串。  
- 申请日前不公开完整协议 Spec；开源规范与参考实现于申请日后发布。  
- Folder/ActionGroup 仅为分层抽象名，可用 Subtask/ActionSet 等替换。

### 5.3 边侧按需补全与逻辑全量拼接（本案相对 C0 的增量要点）

世界状态与拼接装置（300）：

1. **默认路径**：持续接收 T2 增量，维护边侧局部/区域视图（可仍稀疏）。  
2. **缺口判定（示例，可替换）**：任务包围盒未覆盖、某层缺失、版本空洞、模型显式 RequestFill。  
3. **补全动作**：请求端侧补传指定 `layer_id` + 空间范围；和/或从历史库拉取；融合后得到任务窗口内的**逻辑全量视图**（逻辑全量 ≠ 要求端侧每次上传全局全图）。  
4. **多消费者投影（从属/实施例）**：渲染可订几何+语义；规划/WAM 可订语义+位姿+拓扑；执行可订局部几何切片——同一份契约数据按需投影。

**【划界】** 冲突融合、置信度公式等内部世界模型算法引 A3；本案主张**交互链路上的按需补全触发与拼接消费关系**。

### 5.4 世界动作模型的条件输入

T4–T5 的主条件为：

- **契约化拼接地图视图**（绑定 space_version，由各层增量与按需补全结果构成）；  
- 任务意图（文本/符号等）；  
- 可选：图像、检索上下文等辅输入。

**【明确】** 不以「仅模型私有隐状态、无可版本空间视图」作为本方法的默认或唯一条件输入形态。  
世界动作模型装置可替换为 WAM、VLA、VLN+Adapter 等，本案不保护网络结构或训练方法。

### 5.5 任务分层编排（全局策略 / 子任务 / 动作组）

```text
MissionConfig（全局策略：失控/超时/断链等）
  └── Subtask / Folder（子任务路径）
        ├── 路径要素
        ├── startActionGroup（可选）
        └── ActionGroup
              ├── 生效区间 + 触发条件
              ├── 有序动作序列
              └── source_space_version + time + TTL
```

交互载体下行侧为 **ActionGroup（结构化动作）**，与上行 **Token/分地图层数据包** 成对，构成完整空间交互面。

### 5.6 边端版本校验、本地执行与安全降级

| 校验项 | 不通过时行为（示例） |
|---|---|
| 契约版本不兼容 | 拒绝任务 |
| source_space_version 不连续/过旧 | 拒绝或请求基于最新拼接视图重生成 |
| 超过 TTL | 拒绝，目标过期 |
| 本地安全态不允许 | 挂起语义任务，维持安全行为 |

底层速度由本地规划与安全接口生成；模型不是唯一底层控制源。断链时按 MissionConfig 失控策略本地降级。

### 5.7 执行终态回写

回传终态类型、失败原因、关联 space_version 等；写入世界增量，使下一轮补全/拼接/动作生成可感知任务进展与失败区域。

### 5.8 带宽受限时的从属策略（不抢 A4）

当带宽或链路质量受限时，**优先保障空间主层（优选几何层）增量与版本元数据连续**；可暂缓可选语义层或图像辅通道。  
完整「网络质量探针 → 层优先级矩阵 → 传输协议映射」留给论文 ISM-Stream 与 A4，**不作为本案独权核心句**。

### 5.9 与 C0 的衔接

C0：事务、联合触发、分地图层封装与 Token 基础闭环。  
本案：在 C0 上行对象之上，强调 **按需补全、拼接视图、WAM 消费、ActionGroup 编排与安全交互闭环**。  
若上行由其他版本化分地图层增量方式产生，只要满足本案契约，仍落入本案交互方法范围。

### 5.10 系统与装置

- **边端交互装置**：协商、分地图层上行、任务接纳与校验、本地规划、安全、回传。  
- **契约与编排装置**：契约版本、Mission/Subtask/ActionGroup 组装下发。  
- **世界状态与拼接装置**：增量汇聚、按需补全、任务窗口拼接、按消费者投影。  
- **世界动作模型装置**：拼接视图条件输入、动作组生成。  
- 开源组件可用于拼装实施例，不构成独权限制。

## 八、可选实施例

### 实施例一：VLN 顶替 WAM 的最小闭环（对齐 P0-C）

足式机器人按几何+位姿层发布局部增量；边侧拼接后 VLN Adapter 出 ActionGroup；版本校验后 Nav2 类规划执行；回传终态。开源前端/规划仅作实现举例。

### 实施例二：边侧由稀到密——按需补语义层

边侧初始仅有几何+位姿，WAM 请求任务区语义层；编排装置下发补传请求；端侧补 L_sem 增量；拼接后再次推理出动作组。

### 实施例三：版本过期拒绝与重生成

ActionGroup 的 source_space_version 过旧；边端拒绝；基于最新拼接视图重跑 T4–T6。

### 实施例四：断链安全降级

边缘不可达时挂起语义 ActionGroup，本地安全等待；恢复后按新版本重新请求动作。

### 实施例五：多消费者订阅同一契约地图

渲染订几何+语义；WAM 订拼接全层视图；执行订局部几何切片——数据一份，投影不同。

### 实施例六：带宽降级（从属）

弱网时仅传几何+位姿及版本；语义层暂缓；完整 QoS 实验见论文。

### 实施例七：与 A3 世界模型组合

拼接视图写入/查询 A3 类 World State；终态以 Delta 回写；权要可引用不合并独权核心句。

## 十、建议权利要求保护方向

### 10.1 独立权利要求方向

**独权 A（方法）**  
一种基于空间数据流契约的机器人与世界动作模型交互方法，其特征在于包括：  
进行契约版本与能力协商；边端按分地图层发布版本化局部世界增量；边侧将增量合并为可查询视图，并在任务需要时按需补传或融合以在任务窗口内拼接逻辑全量地图视图；世界动作模型以绑定空间版本的该契约化拼接地图视图与任务意图为条件生成结构化动作组；组装携带来源空间版本与时效约束的下行任务；边端校验后由本地规划执行，模型不作为底层速度唯一来源；异常时本地安全降级；回传终态并回写世界状态。

**独权 B（系统）** / **独权 C（边端装置）**：对应实现上述步骤的系统与边端装置。

### 10.2 从属权利要求方向

1. 上行默认局部增量，不包括每次全局全量上送作为唯一方式。  
2. 分地图层包括几何、空间语义、位姿/状态中的至少两层；几何层为优选主层。  
3. 按需补全由覆盖缺口、任务 ROI 或模型请求触发。  
4. 下行包含全局策略、子任务、动作组中至少两层。  
5. 版本不连续或超 TTL 时拒绝或请求重生成。  
6. 模型经 Adapter 替换时动作组语义保持不变。  
7. 多消费者对同一契约地图按需投影。  
8. **带宽受限时优先保障空间主层增量与版本连续**（不主张完整弱网路由体系）。  
9. 与 C0 分地图层 Token 方法组合；与 A3 世界模型方法组合。

| 专利 | 核心句 | 本案关系 |
|---|---|---|
