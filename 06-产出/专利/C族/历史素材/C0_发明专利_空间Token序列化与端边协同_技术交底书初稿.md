## 二、技术领域

本发明涉及机器人同步定位与建图（SLAM）、边缘计算、机器人中间件、视觉-语言导航（VLN）/视觉-语言-动作（VLA）模型调用、空间数据序列化与差分传输、以及机器人本地规划与安全控制技术领域，尤其涉及一种将在线建图端产生的空间状态按**分地图层**组织为版本化增量事务与可解码空间 Token（或等价空间数据包）、卸载至离线语义推理端并回传粗粒度导航目标、由边端本地规划与安全接口执行的端边协同方法、装置及系统。

## 三、背景技术

具身机器人在巡检、导览、仓储与应急等场景中，常需同时完成在线定位建图、本地避障/轨迹执行，以及基于视觉-语言模型的语义级任务理解。现有方案至少存在以下问题：

1. **数据接口断层**
  在线 SLAM 通常输出位姿与稠密点云、网格或占用栅格；离线 VLN/VLA 侧难以直接、稳定地消费海量几何更新，往往需要重复体素化、全量重传或仅依赖原始图像流，导致带宽与算力浪费，且两端难以共享同一空间版本。
2. **时标与算力断层**
  大模型推理与网络传输时延显著慢于本地避障与轨迹控制。若将大模型置于边端（机载）计算平台，会挤占安全与规划资源；若仅上传图像/视频，则边端模型与机载执行器对世界状态缺乏统一、可追溯的几何锚。
3. **闭环与证据断层**
  语义目标、空间版本与执行终态缺乏统一关联。弱网、断连或模型超时发生时，难以区分通信失败、语义失败与运动失败，也难以在语义链路失效时安全降级。
4. **传输组织不当**
  全量点云/高清视频上云在弱网下不可持续；仅做图像压缩又丢失结构化几何；部分多机协同建图方案侧重全局一致与回环，未解决「单机端边语义卸载 + 版本绑定执行」的中间层问题。
5. **边侧视图过稀、层未分离**
  若端侧仅上传单层稀疏几何摘要，边侧拼接结果难以支撑上层动作模型的稳定空间条件输入；几何、语义与位姿状态混在同一不可分割载荷中时，也无法在带宽受限时按层取舍。

在已公开的相关技术中（摘要级摸底，正式申请前须全文核验）：

- 多机 metric-semantic SLAM（如 Kimera-Multi、SlideSLAM 等学术方案）与空地协同建图类中国专利（如 CN116989772B 等）侧重分布式建图一致性，未将版本化增量体素组织为面向 VLN/VLA 的可卸载 Token 契约，也未强调语义目标与空间版本绑定后的本地安全降级。  
- 视觉-语言导航/操作方案（如基于图像或视频的端到端策略）多直接消费像素或端侧局部观测，缺少与在线增量地图事务对齐的中间序列化层。  
- 通用 RPC/消息中间件可传输任意字节流，但不解决「何时抽取关键时空切片、传哪些变化体素、如何与执行终态闭环」的领域组织问题。  
- 行业航线/任务包格式（如公开的 KMZ/WPML 类容器）体现「模板 / 执行 / 资源」分层打包思想，但其资源槽多为媒体文件，**并非**面向机器人分地图层增量世界数据的自有契约；本发明借鉴分层打包思想，**不复制**其字段名与专有结构。  
- 边缘协同 SLAM、按需地图切片、特征级上传等公开实现可作为工程对照，但多未同时给出「分地图层增量契约 + 语义目标版本绑定执行」组织方式。  
- 本申请人族谱中的 A 族方案（多机运行时、子图质量上传、World Model Delta、语义优先弱网）覆盖远场多机与弱网调度，与本发明「单机端边 Spatial Token 闭环」互补而不互相替代。

因此，需要一种把增量空间状态按**分地图层**组织为**可版本化、可差分、可卸载、可回传执行**的中间层方法，使边端保留建图、规划与安全，离线端专注语义推理，并在链路异常时仍可本地保障安全。

## 四、发明目的

本发明旨在提供一种面向视觉-语言机器人模型的空间数据序列化与端边协同方法、装置及系统，解决在线几何难被离线语义模型稳定消费、边端不宜承载大模型、语义目标与空间版本及执行终态缺乏可追溯闭环等问题。

具体目标包括：

1. 将在线建图输出聚合为版本化事务，并按运动条件与几何（或等价空间）变化条件联合触发关键时空切片。
2. 在端侧将局部世界按**分地图层**（优选：几何层、空间语义层、位姿/状态层；层集合可扩展）组织增量，封装为可解码 Spatial Token / 空间数据包，默认传局部增量而非每次全局全量。
3. 将语义推理卸载至离线端；通过可替换 Adapter 派生模型输入；语义端仅输出粗粒度导航目标或动作组，不直接输出底层速度指令。
4. 边端将下行目标与来源空间版本/时间戳关联后交本地规划执行，并通过外部安全接口兜底；语义链路异常时本地规划与安全链可独立运行。
5. 回传执行终态、失败原因及关联空间版本，形成可重放、可归因的闭环。
6. （从属/优选）带宽受限时优先保障空间主层增量与版本连续；细粒度链路自适应调度不作为本母案唯一新颖点。

## 五、技术方案

本技术方案结合附图说明。参见图 1，系统包括边端装置（100）与离线推理装置（200），经通信链路（300）连接。边端装置含：传感器接入与在线建图模块（101）、事务聚合模块（102）、关键切片判定模块（103）、分地图层封装与 Token 编码发送模块（104）、目标接收与版本关联模块（105）、本地规划模块（106）、安全接口模块（107）、结果回传模块（108）。离线推理装置含：Token/分层包解码模块（201）、Adapter 模块（202）、VLN/VLA 推理模块（203）、目标下发模块（204）。对象分层参见图 2；分地图层容器参见图 5；上下行时序参见图 3；失败与安全降级参见图 4。

### 5.1 方法总体流程

```text
S1  在线定位建图，生成位姿流与增量空间状态（优选含哈希体素几何）
S2  按帧或按事件聚合为版本化空间事务
    （至少区分：新增、更新、缓存淘汰、会话重置）
S3  以运动变化条件与空间/几何变化条件联合判定是否形成关键时空切片
S4  对关键切片按分地图层提取增量：
    优选至少包括——几何层、空间语义层、位姿/状态层中的一层或多层；
    默认仅为局部增量，而非端侧每次上送全局全量地图
S5  封装为 Spatial Token / TokenSequence（或等价分地图层空间数据包），
    经通信链路发送至离线语义推理端
S6  离线端按层解码后，经可替换 Adapter 形成模型输入，
    输出粗粒度导航目标或动作组
S7  边端关联目标与来源空间版本/时间戳，交本地规划器执行；
    底层速度指令不由语义模型直接发出
S8  边端通过外部安全接口进行碰撞/急停兜底；
    语义链路失效时本地规划与安全链可独立运行
S9  回传执行终态、失败原因及关联空间版本，形成可追溯闭环
```

### 5.2 版本化体素事务（Producer 事实层）

在线建图模块维护哈希结构增量体素地图（具体哈希实现、滤波器与前端引擎可替换）。事务聚合模块将一段时间内的体素变化组织为**版本化体素事务**，建议包含：


| 字段类别           | 含义（上位）              |
| -------------- | ------------------- |
| session / 会话标识 | 区分一次建图会话            |
| version / 单调版本 | 事务顺序与连续性判据          |
| time / 时间戳     | 与位姿、观测对齐            |
| 事件列表           | 至少包括新增、更新、缓存淘汰、会话重置 |


**【设计决策】** 「缓存淘汰」表示本地缓存生命周期管理，**不得解释为现实世界中障碍物消失**；空间清除须由显式清除类事件或更高层裁决表达（若实施方式需要）。该语义差异建议写入从属权利要求或说明书，避免与占用栅格「自由/占用翻转」混淆。

事务可落盘或环形缓冲，以支持重放与故障归因（对应工程 Gate：增量事务可回放）。

### 5.3 运动与几何联合触发的关键时空切片

关键切片判定模块在满足下列条件之一（或按实施方式配置为「与/或」逻辑）时，从事务流中抽取关键时空切片：

1. **运动条件**：相对上一关键切片的平移或姿态变化超过阈值；和/或
2. **几何变化条件**：相对上一关键切片的体素变化计数、体积或信息增量超过阈值；
3. **可选兜底**：任务指令变更、会话重置、或超时周期触发，防止长期静止导致语义端「饿死」。

阈值、计数方式为可选实施方式参数，**不作为唯一保护范围**。联合触发的技术效果在于：既避免匀速小运动下的无效高频全量发送，也避免大几何变化但机体几乎静止时漏传关键空间更新。

### 5.4 对象分层与分地图层封装（防止独权写窄）

```text
空间事务（Producer 事实）
  → 分地图层增量（几何 / 语义 / 位姿状态 / 可选扩展层）
    → Spatial Token / 空间数据包（稳定语义契约）
      → 网络载荷（具体序列化/分片/传输实现）
        → VLN/VLA 输入（Adapter 派生，可替换）
```

#### 5.4.1 分地图层（优选实施方式，层集合可替换）

| 层（示例名） | 内容（上位） | 角色 |
|---|---|---|
| 几何层 L_geo | 点云块、哈希体素增量、可选距离场补丁等 | **优选主层**：支撑可解码局部几何 |
| 空间语义层 L_sem | 体素/区域标签、实例对象摘要等 | 可选；丰富模型条件 |
| 位姿/状态层 L_pose | 关键位姿、位姿图边、定位置信等 | 优选；对齐时空 |
| 扩展层 | 拓扑关系等 | 可选，不强制 |

**【设计决策】**  
- 独权写「按分地图层组织的版本化局部增量」，**不**将「必须且仅能为几何约束世界模型」写成保护范围硬约束。  
- 层数、层名、具体文件树仅为说明书示例；可用点云、体素、网格等几何表达替换。  
- **默认传局部增量**；全局全量上送不是默认或唯一方式（边侧按需补全见 C2）。

#### 5.4.2 自有空间数据包容器（借鉴分层打包思想，不复制专有格式）

行业公开任务包常采用「元数据 / 执行描述 / 资源目录」分离。本发明优选将「资源目录」替换为**分地图层增量目录**，并使用**自有容器与字段命名**（示例名 `.wmap` / 等价归档，不等于某一厂商 KMZ/WPML）：

```text
spatial_package/                 # 示例容器，字段名可替换
├── manifest                     # session、space_version、坐标系、changed_layers
├── layer_geometry/              # L_geo 增量块
├── layer_semantic/              # L_sem 增量（可缺省）
├── layer_state/                 # L_pose 增量
└── delta_meta/                  # base_version、优先级标签（可选）
```

- **Spatial Token**：对关键切片的稳定编码，至少携带会话/版本/时间，以及至少一个地图层的变化空间条目；可同时携带多层。  
- **网络载荷**：Protobuf、FlatBuffers、自定义二进制或归档分片等——宜进从属/实施例。  
- **Adapter**：将一层或多层投影为模型输入，**不绑定某一模型权重**。  
- 开源 SLAM、消息中间件、规划器仅作**可实现路径举例**，不进入独权。

独权宜钉在：事务 + 联合触发 + **分地图层增量契约** + S6/S7/S8 组织方式；具体 schema 树、路径名仅实施例。

### 5.5 离线语义推理与粗粒度下行

离线推理装置解码 TokenSequence 后：

1. Adapter 生成模型输入；
2. VLN/VLA 推理模块输出**粗粒度**导航目标或动作组，例如：目标点、朝向偏好、途经语义区域、离散动作组中的至少一种；
3. **禁止**由语义模型直接输出轮速/关节级底层速度指令作为唯一控制源；底层速度由边端本地规划器结合安全接口生成。

下行消息建议携带：目标内容、来源空间版本（或版本区间）、时间戳、可选 TTL/最大允许时滞。边端在版本不连续、超时、或本地安全状态不允许时，拒绝执行或请求重规划。

### 5.6 本地规划、安全降级与结果回传

边端目标接收与版本关联模块校验下行目标后，交本地规划模块（2D/局部规划器等，可替换）生成可执行轨迹，经安全接口模块进行碰撞检测、急停或限速兜底。

当出现下列情形之一时，进入**安全降级**（本地自治）：

- 通信链路中断、超时或抖动导致 Token/目标不可用；  
- 空间版本不连续或目标过期；  
- 语义推理失败或返回不可执行目标；

此时本地规划与安全接口仍可基于机载感知继续运行（如保持定位、静止、缓行至安全点），不依赖离线大模型在线可达。

结果回传模块回传：执行终态（到达/超时/拒绝/急停等）、失败原因码、关联空间版本与时间戳，供离线端或运维侧重放与归因。

### 5.7 带宽受限时的层优先（从属一句，不抢 A4 / 不写进论文级调度）

**【设计决策·专利/论文分流】**  
- **本案从属（最多）**：当带宽或链路质量受限时，优先传输空间主层（优选几何层）增量及版本元数据，以维持 `space_version` 连续；可暂缓可选语义层、图像辅通道或扩展层。  
- **不在本案展开**：基于 RTT/丢包/带宽估计的完整优先级矩阵、QUIC/MQTT QoS 细调度、多跳自组网语义路由——上述属申请人 A4 及论文 ISM-Stream 范围，以免重复授权与公开过细。  
- 图像辅通道可选，**不得**作为无版本空间增量时的唯一上行主通道（优选实施方式）。

### 5.8 系统与装置

**边端装置**：实现 S1–S5、S7–S9 对应模块。  
**离线推理装置**：实现 S6 及目标下发。  
**系统**：边端装置 + 通信链路 + 离线推理装置。  
通信链路可为有线、Wi-Fi、蜂窝或自组网等，本发明不限定物理层。

## 六、关键创新点

1. **版本化增量空间事务**作为 Producer 事实层，明确新增/更新/缓存淘汰/会话重置语义，支撑可重放与可归因。
2. **运动条件与空间/几何变化条件联合触发**关键时空切片，兼顾运动稀疏与空间突变。
3. **分地图层局部增量封装**：将几何/语义/位姿状态等组织为可独立取舍的层增量，默认非全局全量；容器可借鉴分层打包思想但字段自有。
4. **契约对象分层**：事务 → 分地图层 → Token/数据包 → 网络载荷 → Adapter，使前端、传输与模型可替换（含开源拼装实现）。
5. **端边职责分离 + 版本闭环**：离线端出粗目标/动作组；边端本地规划与安全执行；目标—空间版本—终态可追溯。
6. （从属）带宽受限时优先保空间主层与版本连续——细调度不抢 A4。

## 八、可选实施例

### 实施例一：单机端边语义导航（主实施例）

轮式或足式移动机器人搭载激光/IMU（可选相机），机载运行在线建图，输出哈希增量体素与位姿；帧级聚合事务；运动或几何变化触发关键切片；编码发送至机旁或边缘计算节点；节点上 VLN 输出粗目标点或动作组；机载 2D/局部规划执行，安全接口急停/避障兜底；回传到达、超时或版本不连续等终态。

> 工程对照（不写入独权）：可对应产品 Gate「增量事务 → Token 编解码 → 世界动作模型闭环」；具体机型与开源前端名称仅作实现举例。
>
>

### 实施例二：干净网络到弱网对照

在实施例一闭环成立后，分别注入限带宽、时延、抖动、丢包、短时断连，记录 Token 新鲜度、过期目标比例、任务成功与安全触发次数，用于说明书有益效果【待补充实测】。

### 实施例三：可替换前端与可替换模型

同一 Token 契约下更换在线建图前端，或更换离线 VLN/VLA 模型与 Adapter，验证中间层不依赖特定引擎/模型，支撑「协议不变量」叙述。

### 实施例四：版本过期拒绝执行

离线端因网络时延下发的目标所携带空间版本落后于边端当前版本超过阈值，或超过 TTL；边端拒绝执行并回传「版本不连续/目标过期」，请求基于最新 Token 重规划，避免时空错位动作。

### 实施例五：分地图层封装与带宽降级（从属）

端侧同时维护几何层、空间语义层、位姿状态层；关键切片触发后将 `changed_layers` 写入 manifest，封装为自有空间数据包上行。带宽充裕时三层同发；带宽劣化时仅发几何层+位姿层及版本元数据，暂缓语义层——**仅体现「优先保主层与版本连续」**，完整 QoS 矩阵见论文/A4。

### 实施例六：开源组件拼装实现路径（不进独权）

边端采用开源激光惯性里程计/建图前端生成增量几何，开源消息中间件传输空间数据包，离线端开源规划栈执行粗目标；中间契约（事务、分地图层、版本、Token）按本发明组织。用于证明本领域技术人员可实现，**不**将任一开源项目名称写入独权。

## 九、替代方案

在不脱离本发明保护范围的前提下，下列替代均可单独或组合使用：

1. 几何层可由哈希体素、八叉树、点云块、网格等表达；具体 SLAM 滤波器可替换。
2. 地图层集合可增减（如增加拓扑层）；语义层可缺省。
3. 联合触发可配置为「或」「与」或加权评分超过阈值；可增加任务事件触发。
4. Token/数据包编码可采用结构化二进制、归档容器、列式压缩或键差分编码等。
5. Adapter 可采用多视图渲染、BEV 投影、点/体素编码器、检索增强上下文等。
6. 下行目标可为点、位姿、航路点序列、离散动作组或高级技能名。
7. 本地规划器与安全接口可替换。
8. 通信可为直连、经由网关、或存储转发。
9. 多机场景下各边端 Token 可按版本合并后再语义调度（建议分案 C3）。

## 十、建议权利要求保护方向

> 以下为内容方向，非法条定稿。阈值、字段名、库名、产品名不进独权。

### 10.1 独立权利要求方向

**独权 A（方法）**  
一种面向视觉-语言机器人模型的空间数据序列化与端边协同方法，其特征在于包括：  
生成位姿与增量空间状态；形成版本化空间事务；按运动条件与空间变化条件联合触发关键切片；将关键切片按分地图层提取局部增量并编码为 Spatial Token 或等价空间数据包发送至离线语义端（默认非每次全局全量）；接收粗粒度导航目标或动作组并关联空间版本后交本地规划执行；语义模型不直接输出底层速度指令；边端在语义链路异常时依赖本地安全接口继续保障安全；回传终态与关联版本。

**独权 B（系统）**  
包括边端装置与离线推理装置，实现独权 A 所述步骤。

**独权 C（边端装置）**  
包括事务聚合、联合触发、分地图层封装与 Token 编码发送、目标执行与安全兜底、结果回传等模块。

### 10.2 从属权利要求方向

1. 事务事件类型至少包括新增、更新、缓存淘汰与会话重置，且缓存淘汰不解释为现实障碍消失。
2. 关键切片还可由任务指令变更或超时兜底触发。
3. 分地图层至少包括几何层、空间语义层、位姿/状态层中的两层或以上；几何层为优选主层而非唯一法定形态。
4. 空间数据包含清单元数据与分层增量目录；清单记录 session、space_version、changed_layers。
5. Token 与网络载荷分离；载荷可采用多种序列化或归档格式。
6. Adapter 将一层或多层投影为模型输入。
7. 下行目标为点/朝向偏好/动作组中的至少一种，并携带版本与可选 TTL。
8. 目标超过时滞阈值或空间版本不连续时拒绝执行或请求重规划。
9. **带宽受限时优先保障空间主层增量与版本连续**（与 A4 划界：不主张完整弱网语义路由/自组网体系；细调度见论文）。
10. 多机 Token 合并调度建议 C3 分案。
