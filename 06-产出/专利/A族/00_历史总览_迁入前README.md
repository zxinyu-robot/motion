## 1. 总体专利布局

本项目不建议把保护点放在单一开源算法上，例如 FAST-LIO、LIO-SAM、EGO-Planner、ROS2 DDS 或某个具体神经网络模型。更适合保护的是系统级技术方案：

- 多形态机器人如何通过统一协议接入同一空间数据运行时；
- 不同机器人产生的位姿、子图、语义观测、任务状态和健康状态如何被结构化组织；
- 边缘端如何根据地图质量、网络状态和任务优先级进行子图接收、融合和调度；
- World Model 如何基于几何地图、语义观测、任务状态和历史数据进行增量更新；
- 机器人运行数据如何转化为可回放、可质检、可训练的具身智能数据集；
- 多机如何在无固定基础设施环境下通过移动自组网互联，并按任务语义价值进行语义化分级回传与可信融合。

建议采用“1 个总架构专利 + 多个子方法专利”的组合方式。

## 2. 首批发明专利建议

### 专利 1：多机异构具身无人系统的空间数据运行时架构

建议名称：

> 一种面向多机异构具身无人系统的空间数据运行时架构及数据处理方法

保护重点：

- 四足机器人、无人机、AGV 等异构平台通过统一 Agent Contract 接入；
- SLAM Runtime 接收多源传感器、局部位姿、关键帧、子图、语义观测和系统状态；
- 边缘端进行时间同步、坐标统一、子图融合、地图质量评估和 World Model 更新；
- 上层通过统一接口查询世界状态、任务状态、地图状态和机器人能力状态。

适合作为主专利，覆盖系统整体架构。

### 专利 2：基于地图质量和系统状态的子图自适应上传融合方法

建议名称：

> 一种基于地图质量评分的多机器人局部子图自适应上传与融合方法

保护重点：

- 根据位姿不确定性、地图重叠度、退化程度、网络状态和任务优先级动态决定子图上传；
- 对子图进行完整性校验、质量评分、跨机器人匹配和鲁棒融合；
- 弱网或边缘负载较高时进行降级传输，例如只上传描述子、稀疏点云、关键帧摘要或延迟上传完整子图。

适合作为 SLAM Runtime 的核心方法专利。

### 专利 3：面向具身无人系统的 World Model 增量更新方法

建议名称：

> 一种面向多机具身无人系统的空间世界模型增量更新与查询方法

保护重点：

- 将 SLAM 地图、语义观测、动态对象、任务状态、机器人状态、通信状态统一成 World State；
- 使用 WorldModelDelta 进行增量更新，而不是每次重建全量世界状态；
- 支持按区域、对象、任务、机器人和时间窗口查询世界状态；
- 支持基于过期时间、置信度和多机器人一致性进行状态更新与冲突处理。

适合作为 World Model 方向的核心方法专利。

### 专利 4：基于语义优先与自组网自适应的空间数据语义化上传融合方法

建议名称：

> 一种面向多机异构具身无人系统的基于语义优先与自组网自适应的空间数据语义化上传与融合方法

保护重点：

- 机器人、可移动中继节点和边缘节点以移动自组网（Ad-hoc / MANET / 无线 Mesh）方式自动组网、动态路由、角色切换和机会式转发；
- 指出现有架构普遍基于 TCP/IP 协议栈，在无线多跳、动态拓扑和弱网下存在重传、拥塞退避、队头阻塞和连接维持开销大等弊端，本方案主张在数据链路层直接进行语义化分级传输；
- 多模链路自适应承载：语义优先级差异化可靠性可映射到 DDS QoS、5G-TSN/TSN（确定性承载）、IEEE 802.11s（无线 Mesh 自组网）、IEEE 802.15.4（低速兜底）等，按链路状态在确定性承载与语义优先尽力传输之间自适应切换，且不绑定任一具体标准；
- 按任务语义价值对空间数据分级（任务关键语义观测、位姿约束与回环、几何摘要、稠密原始几何），带宽受限时优先传"意义"而非全量"比特"；
- 借鉴语义通信思想进行语义提取与联合信源信道编码，结合自组网链路状态自适应调整编码强度、冗余/多路径编码和路由，缓解悬崖效应；
- 通过共享语义字典与编解码版本协商解决跨平台语义互操作问题；
- 边缘端通过多机一致性、几何与协方差校验抑制语义重建幻觉，保证写入 World Model 的状态可信；
- 引入语义保真度、任务完成准确率、约束有效率、单位带宽语义价值等任务级评价指标，替代单纯的比特级指标。

适合作为 SLAM Runtime 在弱网与拒止环境下的通信侧核心方法专利，与专利 2 互补：专利 2 侧重"基于地图质量决定上传什么"，本专利侧重"基于语义价值与自组网链路决定如何语义化编码、组网与可信融合"。

## 3. 后续可扩展发明专利

后续可以继续拆分：

- 一种多形态机器人任务协议转换与协同调度方法；
- 一种机器人运行数据到具身智能 Episode 的自动构建与质量检测方法；
- 一种基于网络状态和地图质量的云边端机器人感知数据卸载方法；
- 一种面向多机巡检任务的空间语义地图构建与异常定位方法；
- 一种基于 Mission Contract、Map Contract 与 Dataset Contract 的机器人任务数据闭环方法。

---

## 4. 软著与专利的分工

软著更适合保护“软件实现”：

- 多机异构 SLAM Runtime 数据采集与融合系统；
- 具身无人系统 World Model 空间状态管理软件；
- 机器人 Mission Contract 与协议管理系统；
- 机器人运行数据质检与 Episode 构建软件；
- 云边端多机器人空间数据闭环管理平台。

发明专利更适合保护“方法与系统机制”：

- 数据如何接入；
- 状态如何统一；
- 子图如何上传与融合；
- World Model 如何增量更新；
- 协议如何让不同机器人共享任务、地图和数据。

## 5. 申请注意事项

1. 在正式提交专利前，避免在公开仓库、公众号、论文、视频或产品文档中公开完整技术细节。
2. 专利交底书应突出“技术问题、技术方案、有益效果”，少写商业愿景，多写可执行流程。
3. 尽量避免把保护点写成“使用某开源算法”，应写成“可替换的前端里程计、局部子图、质量评估和融合流程”。
4. 软著可以先提交，作为项目软件实现资产；发明专利应优先提交主架构和核心方法。
5. 后续交给代理机构时，应让代理人围绕“权利要求 1”重点扩展保护范围，避免写得过窄。
