# 工程落地约束：黑盒本体下的非侵入式接入

> 用途：记录本项目落地必须面对的产业现实约束，并说明这些约束如何塑造技术方案、以及为何它们反而强化专利的创造性与产业价值。
>
> 与《00_项目战略定位_异构平面协同空间建模一致性.md》配套：战略文档定义"做什么"，本文定义"在什么现实约束下做、才落得了地"。
>
> 版本：2026-06-22 · 草案

## 一、落地现实问题（项目方提出）

1. **厂商本体底层不开源（黑盒）**：四足、无人机、AGV 等本体多为厂商商业化产品，其底层固件、原始传感器流、SLAM/控制算法**不对外开放**，对外只暴露有限接口（厂商 SDK、ROS 话题、位姿/状态输出、视频流等），且各家不一致。
2. **下游企业无能力、也无意愿改造本体**：做应用与集成的下游企业不具备本体研发能力，不可能、也不应该为了协同去重写每一种机器人的底层。
3. **现状之痛**：现有"多机协同"多是**针对某一厂商本体做定制化二次开发**——强耦合、不可跨厂商复制、无法规模化。一旦换一种机器人，整套方案推倒重来。

一句话：**你无法要求大疆无人机和某厂四足狗都向你开放底层。任何要落地的协同建模框架，必须默认本体是黑盒、且不可改。**

### 现有市场方案（现有技术基线，⚠️ 不是发明点）

当前市场上抵消"本体底层接口封闭"的通行做法是：

> 在本体上做二次开发，**外挂一个算力盒子**（机载伴随计算单元），盒子里**跑开源框架**（如 ROS + 开源 SLAM/里程计），通过**输出 TF / 位姿**、并用**协议对接本体底层控制**，从而让一台封闭本体"能跑起来、能被控制、能吐出标准位姿"。

这套方案解决的是**单台**黑盒本体的**本体级适配**问题（目的是"控制 + 定位"），**已是现有技术**。因此：

- **"挂算力盒子跑开源框架对接 TF/控制"本身不能作为发明点**，否则会被市场现状驳掉新颖性；
- 它是本项目可以**站上去的地基**，发明点必须落在它**没有解决**的系统级问题上（见第四、五节）。

## 二、由此推导出的硬约束（技术方案必须满足）

| 约束 | 含义 |
|---|---|
| **非侵入** | 不要求改本体固件 / 底层算法 / 控制；本体保持厂商原样。 |
| **旁路接入** | 只消费本体对外暴露的有限接口，能拿到什么用什么。 |
| **能力分级 + 缺失补偿** | 不同本体输出能力不同（有的只给位姿+图像，有的能给点云）；缺什么，由外挂/边缘侧补齐，而非要求本体提供。 |
| **厂商中立** | 不绑定任何单一厂商 SDK / 协议 / 数据格式。 |
| **算力外置** | 本体算力与算法都改不了，故协同建模一致性的"重活"放到机载伴随计算单元或边缘端去做。 |

### 黑盒 ↔ 白盒：本体开放度谱系

上述约束针对**最严苛的一端（黑盒本体）**。现实中本体开放度是一个连续谱系，框架须同时覆盖两端：

| | 黑盒本体（最难端） | 白盒本体（最易端） |
|---|---|---|
| 底层 | 不开源、原始数据不可得、不可改 | 开放、可取原始传感器数据、可深度定制 |
| 接入方式 | 旁路接入 + 边缘侧缺失补偿 | 可深度集成，建模能力可下沉本体 |
| 能力声明内容 | 仅位姿 / 受限数据 | 原始 LiDAR/IMU/图像、可同步时钟、可植入算法 |

**关键：用同一套"能力声明"机制统一覆盖整个谱系**——本体接入时如实声明自己处于谱系何处，框架据此自适应（缺得多就多补、能力全就深用）。这让接入方法不仅适配黑盒，也向下兼容白盒，**权利要求覆盖面更宽、更难规避**。

## 三、可落地的架构取向：黑盒之上的"非侵入式空间数据代理"

核心思路：在每个黑盒本体旁边（机载伴随计算单元，如 Jetson 等）或边缘端，部署一个**外挂式空间数据代理（Agent Adapter）**，它做三件事：

1. **翻译**：把该本体五花八门的对外输出（厂商 SDK / ROS / 视频流 / 位姿），统一翻译成项目标准契约（Agent Contract + 标准观测对象）。
2. **声明能力**：在契约里如实声明"这台本体能提供什么"（仅位姿？带点云？有无时间戳？坐标基准是什么？），供下游按能力分级处理。
3. **补偿缺失**：本体缺的建模能力（如无语义、无高质量子图、无回环），由代理或边缘端用**通用、与厂商无关**的算法补齐。

这样，异构平面协同建模一致性才有落地前提——因为统一与补齐都发生在**黑盒之外**，不依赖任何厂商配合。

---

## 四、为什么这条约束反而加固专利（关键）

1. **它本身就是一个"技术问题"**：在"本体黑盒、原始数据不可得、本体不可改"的受限条件下，仍要实现异构平面建模一致性——这是一个有明确技术难度的问题，**在受限条件下解决问题恰恰支撑创造性**。
2. **划清与学界的差异**：学界方案普遍假设能拿到原始观测、能改前端算法、能统一时钟。本项目主张**非侵入、旁路、缺失补偿**，正好填补"学界有、产业化没有"的空白，是产业化差异点。
3. **重新定位 01**：01 不再是"把现成中间件堆起来"，而是**"黑盒本体之上的非侵入式协同建模承载层"**——这个定位有发明高度，且天然区别于"厂商定制化二次开发"。
4. **强化 02/03/04 的合理性**：因为本体不给高质量子图、不给语义、不给统一坐标，所以才**必须**在边缘端做质量评估补偿（02）、做一致性裁决（03）、在弱网下传"够用的关键信息"（04）。落地约束为这三篇提供了"为什么非这么做不可"的理由。

## 五、独立发明点：非侵入式异构本体接入方法（已确认独立成点）

**该发明点用同一套能力声明机制覆盖"黑盒↔白盒"整个本体开放度谱系（见第二节），黑盒旁路补偿与白盒深度集成是其两个实施例；独立权利要求建议写成"基于能力声明的自适应接入"。**

**与现有技术（第一节现有市场方案）的边界，必须在交底书里写死：**

| 对比维度 | 现有市场方案（现有技术） | 本发明点 |
|---|---|---|
| 目的 | 单台黑盒本体的控制 + 定位 | 跨平面异构本体协同维护**一致世界模型** |
| 层级 | 本体级适配 | 系统级协同建模 |
| 关键技术特征 | 跑开源 SLAM、输出 TF/位姿、对接底层控制协议 | ① **能力声明**：外挂代理向系统声明该本体适配后可稳定提供的建模能力等级（仅位姿 / 带点云 / 有无语义 / 坐标基准 / 时钟质量）；② **缺失能力补偿**：按声明在边缘侧用厂商无关算法补齐建模所需信息；③ 面向异构平面建模一致性的统一契约接入 |

**建议独立专利名称方向**：
> 一种黑盒本体之上基于能力声明与缺失补偿的非侵入式异构平台接入方法（用于多平面协同空间建模）

**背景技术表述方向**：先点现有技术——"现有方案通过本体二次开发外挂算力盒子、运行开源框架输出 TF 位姿并对接底层控制，仅解决单台封闭本体的控制与定位适配，难以跨厂商、跨平面规模化协同"；再写本发明在此之上以能力声明 + 缺失补偿实现系统级协同接入。
