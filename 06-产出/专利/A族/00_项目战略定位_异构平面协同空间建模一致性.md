# 项目战略定位：异构平面协同空间建模一致性

> 用途：统领四篇发明专利的"总纲"。在动笔修改任何一篇交底书、做任何现有技术检索之前，先以本文确定的核心命题为准。
>
> 版本：2026-06-22 · 战略校正草案（替代原"多机异构空间数据运行时架构（中间件）"主线）

---

## 一、一句话核心命题

> **让分布在不同空间平面的异构平台（空中无人机俯视、地面四足/AGV 侧视等），各自建立的空间模型，融合成同一个在几何、语义、时序上都一致的世界模型——本项目保护的是这套"跨平面空间建模一致性"的方法。**

护城河不在"有哪些层/用了哪些中间件"，而在"如何保障异构平面之间建模结果的一致性"。

---

## 二、把三个关键词拆开说清楚

- **异构平面**：平台不仅"型号不同"，更"工作在不同的空间平面/观测维度"——空中是俯视平面（大范围、粗、看屋顶/路网/树冠），地面是水平平面（局部、精、看墙面/门窗/腿下地形）。这是"跨维度"，不是"同一平面里换个型号"。
- **协同空间建模**：多平台共同对**同一物理空间**构建三维空间模型 / World Model（几何 + 语义 + 拓扑 + 时序）。
- **一致性问题（本项目要解决的真问题）**：来自不同平面、不同视角、不同传感模态、不同尺度、不同坐标基准的建模结果，**天然对不上**——共视特征极少、尺度不同、模态不同。如何让它们对齐、融合、消解冲突、增量保持一致，就是核心技术问题。

---

## 三、必须划清的边界：这不是"同层集群协同/协同定位"

| | 同层集群协同（已成熟，不做） | 本项目：异构平面协同建模（要做） |
|---|---|---|
| 平台 | 同质、同一平面（如一群地面机器人） | 异构、跨平面（空 + 地） |
| 视角/模态 | 相近，共视特征多 | 差异极大，共视特征稀少 |
| 要解决的事 | **定位**：算"谁在哪"、互相校正位姿 | **建模一致性**：让"大家建的世界是同一个、不冲突" |
| 难点 | 配准相对容易 | 跨视角/跨模态/跨尺度对齐 + 冲突消解 |
| 现状 | 学界产业都成熟 | 学界有研究，**产业化稀缺** |

一句话：**协同定位是"算坐标"，本项目是"统一世界模型"。前者是后者的手段之一，不是目的。**

---

## 四、场景与落地前提

让"一致性"成为硬问题的两个**场景**条件：

1. **GPS 拒止**：没有统一的全局坐标基准 → 异构平面无法靠 GPS 直接对齐 → 一致性必须靠平台间的空间观测互相建立，难度被放大。这是核心命题成立的关键场景。
2. **弱网 / 全网自适应**：不能全量交换稠密点云 → 只能交换"对建模一致性最关键"的信息 → 一致性与"传什么、怎么传"强绑定。

以及一个决定能否落地的**工程**条件：

3. **本体开放度谱系（黑盒 ↔ 白盒）、按声明自适应接入**：本体从"底层完全不开源的黑盒"（原始数据不可得、不可改）到"底层开放的白盒"（可取原始数据、可深度定制）不等。框架须用**同一套能力声明机制覆盖整个谱系**——黑盒端旁路接入 + 边缘补偿，白盒端深度集成，按本体声明的能力自适应。详见《00_工程落地约束_黑盒本体下的非侵入式接入.md》。

## 五、四篇专利在新主线下的重新归位

新主线 = **异构平面协同空间建模一致性方法**；架构、上传、传输、存储都是为"一致性"服务的手段。

| 专利 | 旧角色 | 新主线下的角色（重新归位） |
|---|---|---|
| **03** World Model | 世界模型增量更新与查询 | **升为核心**：异构平面建模结果的一致性裁决、跨平面冲突消解、增量保持一致 |
| **02** 子图上传融合 | 按地图质量上传 | **几何一致性**：跨平面子图的对齐与融合（尺度/视角差异下的配准） |
| **04** 语义优先弱网传输 | 自组网语义回传 | **一致性所需信息的高效交换**：弱网/GPS 拒止下只传对跨平面对齐最关键的语义/约束 |
| **01** 运行时架构 | 中间件总架构 | **承载体**：异构平面协同建模流水线的编排（"管理方法/流程"），不再以"架构堆叠"为卖点 |

## 六、与"管理方法/流程"主张的衔接

项目最初的判断——"发明点在系统的管理方法、数据输入输出的流水线流程"——依然成立，且现在有了明确**目标**：

> 这套流水线管理方法所要达成的，就是**异构平面建模的一致性**。即"在什么条件下、按什么规则，让空、地平台交换什么信息、如何对齐、如何消解冲突、如何增量维持一个一致的世界模型"。
