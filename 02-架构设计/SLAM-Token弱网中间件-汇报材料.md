## 1. Executive Summary

### 1.1 痛点一句话

**弱网、无 GPS 环境下，SLAM 产出的几何世界与上层智能（VLA / 调度大脑）之间没有标准接口，而边端算力又塞不下大模型。**

具体表现为三个断层：

- **数据断层**：SLAM 输出止步于里程计 + 点云，大模型只吃图像 + 文本，中间靠人肉二次开发翻译，信息一路损耗；
- **算力/时延断层**：大脑必须慢（大模型推理约 10 秒/步），小脑必须快（毫秒级避障），两者挤在同一颗边端芯片上互相拖累；
- **调度断层**：传统 RPC 调度调不动"帮我找那个不知道在哪的杯子"这类语义任务，且主流方案（如仙工）依赖预先建图和稳定网络。
- **【设计决策】** 可在内部建立 SLAM–VLN 联合评测：除导航成功率外，测 Token 编解码、版本连续、新鲜度、单位成功任务传输量与边端资源；能否成为公共基准须在专利申请、实测和外部合作后另行判断。
- 两端模型的定义者不只是定义数据格式，还要定义「模型能力的边界」：SLAM 端通过 Adapter 输出前端无关的 `SpatialChunk/VoxelDiff`、关键帧和位姿；VLN/VLA 端消费文本、Graph 子图和相关空间块，输出 Folder / coarse waypoint 而不是 raw `/cmd_vel`。
- 抽象成「兼容各类SLAM引擎的通用规范」
- **【设计决策】** 先形成 internal `TokenSequence v0.1` 与 Benchmark，不对外承诺 Spec v1.0、组织捐赠、厂商数量或标准地位。
- **专利边界**：专利范围和分案仅以 `06-产出/专利/专利族谱映射.md` 为准；申请前不在本汇报扩写完整方法，也不作授权结果预测。

### 1.2 解决方案

**SLAM-Token 中间件（当前设计）**：边端将 OctVox 帧级增量形成版本化事务与 TokenSequence，经现有 IP 网络送至 x86 VLN Adapter；语义结果以 waypoint/ActionGroup 回传，由当前 Nav2 2D 与固件安全链执行。带宽、实时性和断网降级效果均须由 P0-B～P0-D 实测，不能使用历史估算代替。

| 现有玩家                   | 在卖什么            | 缺什么                          |

| LiDAR 厂（Livox/Ouster）  | 硬件 + 内置 LIO 定位  | 输出止步 odom/cloud，接大模型需二次开发    |

### 2.5 壁垒的诚实说明

SLAM 引擎及其内部 Local Map 实现**不是**本项目自有 IP，具体版本与许可证需按 `motion_ws` 核对。真正壁垒在三层：

1. **Tokenizer 协议**——谁先定 schema 谁占坑（对应切片 C 的"要快"）；
2. **双触发关键帧策略**——弱网流量控制的 heuristic 是调出来的 know-how；
3. **下游对接中间件**——SLAM 厂不懂 VLA、VLA 厂不懂 SLAM，翻译层才是卖点。

类比：SLAM 是 MySQL，VLA 是 GPT，我们做的是 ETL 管道 + 标准 schema——不性感，但谁用都绕不开。

## 4. 为什么主打弱网：场景即护城河

弱网不是缺陷补丁，而是**主动选择的战场**。理由有三：

1. **真实场景就是弱网**：仓储、工厂、地下、楼宇夹层、应急救援——无 GPS、WiFi 抖动、5G 覆盖不稳。云端大模型方案在演示厅里都好用，到客户现场第一个死的就是网络假设。
2. **弱网天然筛掉竞争者**：
  - 纯云端 VLA 方案（依赖持续大带宽视频流）在弱网直接失效；
  - 纯边端方案（大模型压上本体）受算力限制，避障精度与智能水平二选一；
  - 我们的分层架构目标是在弱网下同时保留本地安全能力与可恢复的上层语义链；相对收益须由 P0-D Benchmark 证明，不能预先宣称“唯一”。
3. **弱网对齐产品与学术两条线**：产品端对标仙工的"弱网/免建图"差异化；学术端命中"弱网边缘的通信高效 C-SLAM / 轻量化协同世界模型"论文点（详见 §7）。

**弱网下的量化账（历史估算，非当前实测）：**


| 项        | 数值                                  | 含义                    |
| -------- | ----------------------------------- | --------------------- |
| 关键帧带宽    | 历史估算：~100KB/帧 × 平均 2Hz ≈ 200KB/s | 实际 payload、频率与协议开销须由 P0-B/D 实测 |
| 对比：原始点云流 | 数 MB/s 起                            | 弱网下不可行，这就是 Token 化的价值 |
| 断网降级     | 当前设计：Nav2 2D + L1 固件/estop 独立工作 | 具体触发与恢复行为以 P0-D 实测为准 |
| 语义恢复     | 目标：网络恢复后按版本恢复增量链路 | 断点续传语义与实现仍待冻结 |

## 5. 痛点讲透：一个断层的三个尺度

### 5.1 数据断层（单机尺度）

现有链路：`SLAM → /odom + /pointcloud →（断崖）→ VLA 只吃 RGB + 文本`。

- 对标工作的局限：NaVILA 的 VLA 只吃 RGB（3D 只给底层运动控制）；MobileVLA-R1 用 PTv3 吃瞬时点云，是隐式表征、每帧全量消化，带宽与算力双冗余；
- 传统"encoder-decoder 翻译"路线每过一次「几何↔语言」翻译就丢一次信息（信息熵损失）。

**解法：不翻译，直接序列化。** OctVox 哈希增量体素天然可 diff、可 merge、可转 token——每个变化体素仅序列化 `哈希键 + 中心坐标 + 命中次数 + 强度`，几十字节，跳过"点云→重新体素化→再编码"的二次消化。

### 5.2 算力/时延断层（边云尺度，被弱网放大）

边端资源账目前【待补充实测】。P0 设计上把 VLN/VLA 放在 x86，但 Encoder、传输、Nav2 与安全链的 CPU/内存/时延仍须分模块测量；不得把论文图中的 CPU 百分比误作本仓帧耗时，也不得据历史估算宣称避障精度变化。

**解法：时空解耦 + 四级分层，弱网即降级链。**


| 层级        | 执行方             | 频率/精度    | 弱网表现            |
| --------- | --------------- | -------- | --------------- |
| L1 固件级    | Unitree 固件 / estop | 以实测配置为准 | 不依赖 x86 语义链 |
| L2 规划级    | Nav2 2D（当前 P0） | 以 `40-验证/` 为准 | 本地轨迹与到达 |
| L3 演进规划 | ego / 3D planner | 【待补充】 | 过 Gate 后替换 |
| L4 语义级    | x86 VLN Adapter | 【待补充实测】 | 输出 waypoint/ActionGroup |


原则：**VLN/VLA 永不直接发速度指令；L1/L2 不依赖 x86 语义链。** 触发条件与弱网自适应策略属于 patent-sensitive 内部设计，是否有效须由 Benchmark 裁决。

### 5.3 调度断层（多机尺度）

典型场景（来自工作计划）：A 机器人在一楼，B 在二楼，A 想让 B 把第二个房间里的杯子拿下来——A 不知道 B 在哪，B 不知道杯子在哪。**按 RPC 调度，除非预知杯子位置，否则无法闭环。**

根源：传统 Fleet 调度（含仙工）的任务原语是"去 A 点取货→B 点放"，分配依据是距离/TSP/电量等几何量；"找一个不知道在哪的杯子"是语义任务，RPC 范式里没有对应原语。仙工的两个软肋（需预先建图、狭窄货道轨迹不灵敏）同根同源：其世界模型是静态 2D 栅格，既不增量也不语义。

**解法：Token 上传 + 体素 merge + VLA 语义调度中枢。**

- 各机器人经 RPC 上报关键帧 Token（`UploadKeyFrame`），网关将各机 OctVox 哈希 merge 为全局增量 3D 地图——"B 的视角实时共享给 A"在工程上就是这个 merge；
- VLA 吃「全局体素 + 多视角 RGB + 语义指令」，输出 per-robot waypoint 序列 + 协同提示（`GetTask`）；
- 冲突兜底仍分层：语义分工归 VLA，粗粒度区域锁归规则引擎；本地避碰归各机规划器与 L1 安全链，当前基线为 Nav2 2D + 固件/estop，后续规划器须过 Gate。

**杯子场景 = 本架构的验收用例**：它闭环之日，就是调度断层补上之时。

## 6. 方案：SLAM-Token 中间件架构

### 6.1 单机目标数据流（尚未全链验证）

```
[边端 Go2 / Orin]
  Livox Mid-360 + IMU
       ↓
  SLAM 前端（可插拔：Super-LIO / FAST-LIO2）+ Local Map
       ↓
  Adapter → KeyFrame + SpatialChunk/VoxelDiff
       ├─→ 本机低拷贝 → Recorder / Nav2 视图
       └─→ 弱网数据面 → [PC/网关]
                              ├─ Pose Graph / Graph Node 索引
                              ├─ 点云语义分割 / 三维重建
                              └─ text + Folder scope → 子图检索 → VLN
                                                       ↓
                                             Folder + Coarse Waypoint
                                                       ↓
                                          ActionGroup + Trigger
       ↓
  Nav2 2D（当前 P0）→ /cmd_vel → Unitree 固件 / estop 安全链
```

**架构铁律：协议是不变量，前端是可换件。** 对外只暴露统一 KeyFrame + SpatialChunk/VoxelDiff + Graph Node 引用；单机 demo 与多机线都经 Adapter 输出同一契约。传输载体同理：P0 依据 benchmark 在 Fast DDS、Zenoh 与本机共享内存中选择组合——**换的是运输车，不是货物格式**。

### 6.2 多机升级（同一协议，零改边端）

```
Go2 #1 ─┐                    ┌─ 版本化 SpatialChunk merge
Go2 #2 ─┤→ Token 协议 → 网关 ─┤─ Pose Graph / Graph Node 空间索引
X2/T800─┘                    ├─ VLN 语义调度（per-robot Folder/waypoint）
                            └─ 规则引擎（区域锁/交通管制）
```

单机↔多机模块映射（证明 Go2 demo 是网关产品的最小切片）：


| 单机（技术方案）              | 多机（协同网关规划）         | 同一件事    |
| --------------------- | ------------------ | ------- |
| 边端 SLAM + 当前 Nav2 2D，VLN 在 x86 | 前端在线 + 后端网关离线 | 边云/边网分工 |
| Local Map → SpatialChunk/VoxelDiff | 在线增量建图目标 | 减少预先建图依赖须实测 |
| KeyFrame/SpatialChunk/GraphNode 契约 | 协议翻译网关 + 统一中间件 | 标准接口 |
| 双触发关键帧                | 带宽-置信度感知关键帧压缩（论文点） | 弱网流量控制  |
| Nav2 2D + L1 固件/estop；断网保留本地链 | 弱网断连恢复（后续验收指标） | 降级安全 |
| VLA+RPC 调度（专利分案）      | 调度大脑 + 群体智能 + 杯子场景 | 语义调度    |

## 7. 产品线与学术线的分离（同源分流）

**原则：一套架构、一份数据、两条产出线。产品线不碰模型训练，学术线不阻塞产品交付；分叉点清晰，汇合点在协议。**

### 7.1 分工表


|            | 产品线（工程/落地）                            | 学术线（论文/合作）                                                      |
| ---------- | ------------------------------------- | --------------------------------------------------------------- |
| **主体工作**   | Tokenizer 中间件、协议 SDK、硬件盒、网关调度         | 弱网协同世界模型、异构混编、通信高效 C-SLAM                                       |
| **对模型的态度** | inference-only，用现成权重（NaVILA 等），模型可换   | 训练/压缩/鲁棒性研究                                                     |
| **人员要求**   | SLAM 工程师舒适区：TF 对齐、去畸变、C++ 节点、Protobuf | 对齐领导方向：陈涛（边缘 AI Infra）、余翀（模型压缩+群体协同）                            |
| **复用资产**   | 开源 SLAM 前端（可插拔）                       | LL3DA（点云直入 3D-LLM）、MADTP（token 剪枝 −80% GFLOPs）、BRCB（鲁棒压缩，合作切入点） |
| **交付物**    | Demo → lib 剥离 → 硬件盒 → 网关              | 论文 3 篇方向 + 专利族                                                  |
| **时间压力**   | 快（协议标准窗口期 1–2 年）                      | 稳（顶会节奏）                                                         |


### 7.2 同源分流：专利归产品，论文归学术

同一个技术点，专利与论文各取所需、互不重复：


| 技术点                           | → 专利（产品护城河）                     | → 论文（学术差异化）                                             |
| ----------------------------- | ------------------------------- | ------------------------------------------------------- |
| 双触发关键帧 + 体素 diff 序列化          | 主专利：面向 VLA 的 SLAM 数据序列化方法、装置及系统 | 论文点③：带宽-置信度感知的关键帧压缩与调度（IROS/RA-L）                       |
| 体素→token 编码（三视图/Minkowski）    | 分案 1：体素 Token 编码方法              | 并入论文点①的方法部分                                             |
| 端边分工 + coarse waypoint/ActionGroup + 安全兜底 | 分案候选：端边协同 VLN 导航控制（以专利族谱为准） | 申请后再按 measured 证据确定论文问题与 venue，不预判命中率 |
| VLA + RPC 多机调度 + 体素 merge     | 分案 3：基于 VLA 的多机 SLAM-Token 调度方法 | 论文点②：异构运动学混编 + 跨楼层协同（ICRA/IROS）                         |
| 免建图前后端分离、DDS-TSN、零拷贝          | 多机专利族（4 件）                      | **不单独发论文**（edgeSLAM2/Fast DDS 已做透，新颖性不足——适合专利不适合顶会）     |


### 7.3 边界纪律（防两线互相拖累）

- 产品线**不等**论文结果：切片 A/C 用现成 VLA 权重即可交付，SFT/GRPO/CoT 数据等训练工作全部划归学术线；
- 学术线**不改**协议：论文实验基于同一份 KeyFrame/VoxelDiff schema 产数据（跑一趟录一趟 bag，产品 demo 与论文数据集同源）；
- 弱网是两线共同的叙事词根：产品端讲"断网不瘫痪"，学术端讲"通信高效/轻量化协同"——对外是一个故事的两个面。

## 8. 里程碑（两线并行、单点汇合）


| 阶段  | 时间     | 产品线                                                     | 学术线                            |
| --- | ------ | ------------------------------------------------------- | ------------------------------ |
| L1  | 当前     | Go2 单机：VoxelTransaction → TokenSequence → x86 VLN → waypoint/ActionGroup → Nav2 2D/L1 → 结果回传；按 P0-A～P0-D 验收 | 录制 bag/日志，先补工程证据 |
| L2  | P0 通过后复核 | Adapter / schema 候选收敛；是否形成协议冻结点由实现、专利与兼容 Gate 裁决 | 论文点③仅保留实验设计 |
| L3  | 后续 proposal | Graph Node 索引 + 硬件盒 Design Partner 验证；Swarm-SLAM 仍须先过 Gate | 形成模型显存/延迟/SR/SPL 基线 |
| L4  | 长期愿景 | Token+规划、多底盘适配和多机网关任务编排 | 异构混编研究与专利分流 |


**当前冻结边界**：已冻结的是产品切入点与 P0-A～P0-D 排序，协议 schema 仍为草案。产品/学术实验可共享内部数据，但不得把时间表当作 Spec 已冻结或即将对外发布的证据。

## 9. 资源请求（Ask）

1. **专利费用**：主专利 + 3 分案启动（产品护城河，窗口期敏感）；
2. **人力编制**：1 名中间件开发（C++/Protobuf/DDS），专职 tokenizer 库与协议 SDK——这是产品线与学术线共用的唯一新增岗位；
3. **商务对接**：引荐 2–3 家 AMR/四足厂商做切片 A 送测；
4. **学术合作（条件触发）**：当基线确认模型推理是主要瓶颈后，再与余翀团队评估 MADTP/BRCB 复现；不阻塞协议、Graph 检索与任务闭环。
