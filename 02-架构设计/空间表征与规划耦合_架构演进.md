# 空间表征与规划耦合：架构演进路线

> **定位**：在现有 SLAM-Token 端边链路之上，记录从“状态估计/建图”向“统一空间表征驱动规划”演进的架构边界。  
> **当前结论**：这是架构演进方向，不替换当前 P0 主链。  
> **保密**：`internal`；涉及 C 族未申请核心机制时，不展开可直接用于专利撰写的完整方法细节。

---

## 1. 核心判断

**【事实】** 多传感器融合在传统机器人系统中主要承担状态估计与建图，输出位姿、点云、栅格或体素等空间信息；规划器基于这些信息生成轨迹并交给控制/安全链执行。

**【设计决策】** 本项目把演进重点放在中间的“统一空间表征”层，而不是简单把融合模块直接并入规划器。该层负责组织：

- 几何：体素、表面、占据和空间版本；
- 语义：对象、地形类别和任务相关属性；
- 可通行性：坡度、粗糙度、障碍风险和通过概率；
- 动态性：变化状态、时效和置信度；
- 任务关联：观测价值、目标区域和规划约束。

这样可以在保持 SLAM、编码、规划和安全执行解耦的同时，让规划消费比 `occupied/free` 更丰富的空间信息。

## 2. 架构演进

```text
传感器
  ↓
状态估计与增量建图
  ↓
统一空间表征
  ├─ 几何 / 版本 / 置信度
  ├─ 语义 / 地形 / 可通行性
  ├─ 动态性 / 时效 / 任务价值
  ↓
规划与决策
  ├─ 已知地图导航
  ├─ 地形感知规划
  └─ 主动观测 / 探索
  ↓
控制与安全执行
```

对应当前产品链路：

```text
Super-LIO / OctVox
  → VoxelTransaction
  → TokenSequence
  → x86 VLN Adapter
  → waypoint / ActionGroup
  → Nav2 2D + L1 安全链
```

**【事实】** 当前 P0 的真实入口和执行边界见 `Go2-VLA-SLAM-Token技术方案.md` §2：Token 链路负责空间增量数据与语义结果的可追溯交换；VLN 不直接发 `/cmd_vel`；Nav2 2D 与 L1 安全链仍是当前执行边界。

## 3. 三类融合—规划耦合

### 3.1 Traversability-aware Mapping

**【推断】** 对 Go2 等足式平台，仅提供占据/空闲的地图接口不足以表达草地、泥地、台阶、玻璃、坡面或高粗糙度区域的通行风险。

空间单元可以逐步演进为：

```text
cell = {
  geometry,
  elevation,
  slope,
  roughness,
  semantic,
  traversability,
  risk,
  confidence,
  version
}
```

其中 `traversability` 不应被直接视为真实标签，而应与置信度、观测时效和机器人能力模型一起进入代价计算。

**【待补充】** 当前项目尚未形成 Go2 地形类别、可通行性标注、代价模型和首组实测数据；因此本节不升级为 P0 实现承诺。

### 3.2 Active Mapping / Exploration

Scan Planner、Next Best View 和探索规划解决的不是“已知地图上怎么走”，而是“下一步观测哪里最有价值”。

```text
当前空间表征
  ↓
候选观测 / 目标区域
  ↓
信息增益 − 运动代价 − 通信代价 − 风险
  ↓
选择下一次观测
  ↓
增量更新空间表征
```

在多机器人场景中，可进一步分配不同机器人负责不同区域，但必须先具备覆盖率、信息增益、通信消耗和任务成功率的可复现实验定义。

### 3.3 Planning-aware SLAM

传统 SLAM 主要优化状态估计与地图一致性；Planning-aware SLAM 则将任务相关的地图质量或规划代价反馈给观测、建图或资源调度。

**【设计决策】** 本项目暂不把规划目标直接写入 P0 的状态估计优化器。先通过统一空间表征和版本化 Token 接口传递规划所需信息，再用独立 Gate 评估反馈耦合是否值得进入主线。

原因是直接耦合会引入：

- 任务变化导致估计目标变化；
- 规划失败与定位/建图失败难以归因；
- 计算、时延和安全链耦合；
- 现有 P0 Benchmark 无法区分收益来源。

## 4. 与当前路线的分层

| 层级 | 主题 | 当前角色 | 进入条件 |
|------|------|----------|----------|
| P0 | 增量几何 Token 与 VLN/导航闭环 | 主链 | P0-A～P0-C |
| P1 | 语义 / 地形 / Traversability 表征 | 扩展候选 | 地形数据、代价模型、Go2 验证 |
| P2 | Active Mapping / Scan Planner | 探索方向 | 信息增益与弱网代价 Benchmark |
| P2 | Planning-aware SLAM | 耦合研究方向 | 证实独立接口不足，并通过适配 Gate |
| 远期 | World Model / Neural Spatial Memory | 上层空间记忆 | World Model 增量更新与多机证据成熟 |

**【设计决策】** 这一路线不改变当前 WIP 上限 3，也不把 3D 规划、主动探索或 MARL 直接纳入当前 P0。

地图底座与规划部署位置按 `Nav2端边解耦与地图任务契约_两阶段演进.md` 推进：先保留本地 Nav2 完整栈完成地图上送和 x86 维护，再评估边侧全局规划；统一空间表征不依赖提前拆分 Nav2。

## 5. 关键接口原则

1. **空间表征先于规划器耦合**：规划器消费稳定的空间对象，不直接依赖某个 LIO 或具体神经网络。
2. **规划结果不越过安全边界**：语义模型输出 waypoint/ActionGroup；本地规划、控制和 L1 安全链负责最终执行。
3. **版本与置信度随空间信息传播**：任何规划输入都应能追溯到空间版本、观测时效和来源。
4. **主动观测是闭环触发，不是单向输出**：规划选择观测后，必须能回到增量建图与验证链。
5. **先证实再耦合**：没有问题证据、收益指标、故障隔离和回退路径，不替换 P0 主线。

| 方向 | downstream_artifact | acceptance | evidence_target |
|------|---------------------|------------|-----------------|
| Traversability | 地形/可通行性空间对象草案；Go2 小规模数据集 | 同一场景可重放；代价输入有版本和置信度；不破坏 P0 导航 | bag、地图快照、代价统计、失败分类 |
