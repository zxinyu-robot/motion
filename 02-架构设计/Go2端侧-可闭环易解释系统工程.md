# Go2 端侧可闭环、易解释系统工程实现路径

> **定位**：Go2 端侧 P0 的架构约束与验收框架。以版本化增量哈希体素为状态底座，以可重放的事件链实现从感知到安全执行的工程闭环。  
> **阅读优先级**：高。涉及 Go2 端侧实现、协议、验证或复盘前，先读本文件，再读 `02-架构设计/Go2-VLA-SLAM-Token技术方案.md` 与对应 Benchmark。  
> **保密**：本文包含未冻结的内部接口与事务模型，按 `patent-sensitive` 管理；不得作为申请日前的公开 Spec 或论文方法细节。

---

## 1. 目标与边界

### 1.1 目标

本项目的端侧目标不是先叠加复杂模型，而是建立一个每次行为均可回答“输入是什么、为何决策、如何执行、结果如何”的闭环系统：

```text
观测
  → PoseStream + VoxelTransaction
  → 空间状态版本
  → ActionGroup / waypoint
  → 时滞对齐与安全校验
  → 局部轨迹
  → cmd_vel / L1 兜底
  → 结果、状态与版本回传
```

**【事实】** 当前 Go2 单机基线为 Super-LIO、SHM 静态层至 Nav2 costmap、Nav2 2D（MPPI）和 Unitree Sport / 固件加 `estop_go2` 的避障链路；真机 2 m 到达尚未达标，停栈后静止待复测。来源：`40-验证/BENCH-P0-Go2-MotionSLAM-基线.md`。

**【设计决策】** 后续端侧数据流以“版本化增量哈希体素契约”作为下游依赖；当前 Super-LIO 是该契约的首个 Producer，不应成为 Token、导航或记录模块的直接耦合对象。

### 1.2 非目标

- P0 不引入以 SHAP、LIME、LaGNA 等为主的事后黑盒解释作为闭环前提。
- P0 不将云端/PC VLA 放到 Go2 端侧，也不允许 VLA 直接发送 `/cmd_vel`。
- P0 不把 LRU 内存淘汰解释为现实障碍物消失。
- 本文不定义公开的完整 Token schema、双触发阈值或专利权利要求级实现。

## 2. 可解释性的工程定义

本项目所称“易解释”不是输出一段自然语言说明，而是通过状态版本、结构化事件与可重放证据，使每个结果可被确定性追溯：

1. **输入可追溯**：观测、位姿、地图会话、时间戳和体素版本均可定位。
2. **决策可归因**：下行目标的来源、时滞修正、安全接受或拒绝原因均有事件。
3. **执行可观测**：局部规划状态、轨迹、控制输出、L1/L2 介入均有记录。
4. **结果可验证**：到达、超时、不可达、安全拒绝等终态可与 bag、日志和 Benchmark 对齐。
5. **失败可优化**：相同输入可重放；失败按稳定错误码归因，而非笼统标记为“失败”。

## 3. 状态底座与模块边界

### 3.1 Producer、契约与派生视图

```text
Mid-360 + IMU
      ↓
SLAM Producer（当前：Super-LIO）
      ├── PoseStream
      └── VoxelTransaction
               ↓
     Versioned HashVoxel Contract
      ├── Token/FST 编码视图
      ├── NavVox 导航视图
      ├── ReLoc/Matching 视图
      ├── Recorder
      └── Visualization
```

**【设计决策】** 统一的是键、版本、事务与增量语义，不要求所有消费者共享同一个物理体素容器。

| 视图 | 主要用途 | 生命周期 / 语义要求 |
|---|---|---|
| MatchVox | 前端匹配、局部几何查询 | 低延迟；可有受限容量和缓存淘汰 |
| NavVox | 局部导航与障碍约束 | 需区分占据、清除、动态障碍与机器人膨胀 |
| TokenVox | FST/FSLP 增量编码 | 稳定键、多尺度、量化特征与版本连续性 |
| ReLocVox | 重定位与长期匹配 | 尽量不受短期 LRU 淘汰语义影响 |

### 3.2 事件语义

| 事件 | 含义 | 不应误解为 |
|---|---|---|
| `ADD` | 新键首次进入当前状态 | 完整地图永久新增 |
| `UPDATE` | 该键的有效内容实际改变 | 接收到点即一定改变 |
| `REMOVE` | 经明确清除策略确认的空间移除 | LRU 淘汰 |
| `EVICT` | 因容量或缓存策略移除 | 现实空间变空 |
| `RESET` | 会话、重定位或地图状态失效 | 单个体素更新 |

**【待补充】** `REMOVE` 的生产条件。当前 P0 基线中尚未确认有射线清除或时间衰减机制，未实现前不得生成带“真实空间已清空”含义的 `REMOVE`。

### 3.3 最小事务契约

每帧应提交一次原子事务，同帧同一体素只保留最终状态，避免按点发布事件。

```text
VoxelTransaction {
  schema_version
  map_id, session_id
  base_version, commit_version
  timestamp_ns, world_T_base
  added[], updated[], removed[], evicted[]
}
```

字段名称与实际数据类型在 schema 冻结任务 T-003 中确认；以上为【设计草案】，不是已实现接口。

### 3.4 显式状态与学习型隐状态边界

**【设计决策】** P0 的系统事实源仍是可版本化、可记录和可重放的显式状态，包括 `PoseStream`、`VoxelTransaction`、地图会话/版本、ActionGroup/waypoint、执行终态与失败码。POMDP 可作为后续“观测—信念—动作—反馈”的形式化框架，但不改变这些状态的所有权和证据要求。

ESN、LSTM/GRU 或其他时序模型产生的隐状态，只能作为后续动态目标预测或社交元控制的派生输入：

```text
显式状态 + DynamicActorStream + 历史执行结果
  → 可替换时序编码器（候选：ESN）
  → 动态隐状态 / 预测及置信度
  → Belief Adapter / 社交元控制
  → 既有 waypoint/ActionGroup 或局部规划约束
```

- 不把任意神经网络隐向量直接宣称为概率校准的 POMDP belief；
- 不允许学习型隐状态替代 `map/session/version`、安全状态或机器可读失败码；
- ESN/PPO 不直接发布 `/cmd_vel`，不得越过 Nav2/局部规划和 L1 安全链；
- 模型不可用、置信度不足或通信中断时，退回显式状态、现有规划器与端侧安全链；
- 该能力属于门闩后的隔离支线，不改变 P0-A～P0-D 的顺序；准入须以常速度模型、MLP、LSTM/GRU 等同场景基线进行单变量对照。

相关分析与门闩见 `03-技术分析/社交导航_ESN-PPO-绕行停等支线.md`。

## 4. 低拷贝、可并发实现原则

### 4.1 目标边界

“零开销拷贝”应更准确表述为：**不复制原始点云、无 ROS 消息中转、单次编码、零中间大对象拷贝**。

FST 量化、序列化与网络传输本身必然产生写入；内核协议栈、DMA 和对端接收也不构成端到端零拷贝保证。

### 4.2 推荐路径

```text
SLAM Commit
  → 预分配、不可变 DeltaBlock
  → SPSC 队列 / 只读 Handle
       ├── Token Encoder
       ├── Nav Projection
       └── Recorder
  → 引用计数或 epoch 完成后归还内存池
```

- SLAM 线程只提交帧级聚合后的紧凑体素快照，不复制原始点云。
- 消费者读取提交后的不可变 `DeltaBlock`，不直接读取正在变更的体素对象。
- FST Encoder 一次量化到预分配 FSLP Buffer；发送层可采用 Buffer 所有权转移，避免再拼接大 payload。
- 实际队列、内存池、消息库 API 和线程模型须以 `motion_ws` 中的实现为准。

### 4.3 不采用裸指针跨线程读取

**【推断】** 直接传递可变体素对象指针会面临并发修改、淘汰失效与 reset 释放等风险。除非后续证明具备不可变快照、generation 校验、延迟回收以及并发读写约束，否则 P0 采用紧凑快照，不以“理论零中间拷贝”为目标。

## 5. 端侧闭环与安全边界

```text
空间增量上行
  → 边侧 / VLA 产生 ActionGroup 或 waypoint
  → 端侧关联 map/session/version
  → 时滞对齐与安全校验
  → Nav2 2D（当前）或后续局部规划器
  → /cmd_vel
  → Unitree 固件 L1 与 estop
  → 终态及证据回传
```

**【事实】** 当前架构规定 VLA 不直接发 `/cmd_vel`，并保留 L1/L2 兜底。来源：`02-架构设计/Go2-VLA-SLAM-Token技术方案.md` §2.2。

**【设计决策】** 下行目标至少关联来源会话、空间版本与产生时间；版本断链、会话失效、超出时滞边界或规划不可行时，应拒绝、重请求或降级，而不是盲目执行。

断网时，端侧必须能依靠已确认安全的 L1/L2 降级运行；云端或网关不可成为急停与基本避障的必要条件。

## 6. 证据与失败归因

### 6.1 每次任务的最小证据包

| 层 | 最小证据 |
|---|---|
| 感知 / 建图 | `session_id`、时间戳、关联位姿、事务版本与事件摘要 |
| 通信 | payload 版本、发送/接收时间、延迟、丢包或重传事件 |
| 决策 | ActionGroup/waypoint、来源空间版本、时滞修正或拒绝理由 |
| 规划 | 规划器状态、约束摘要、轨迹或不可行原因 |
| 安全 | L1/L2 触发、estop、降级状态 |
| 结果 | 终态、到达误差、任务时间、碰撞和 bag/日志回链 |

### 6.2 建议终态 / 错误码

下列为【设计草案】，需在实现前统一为机器可读枚举：

| 代码 | 含义 |
|---|---|
| `SUCCESS` | 满足任务完成条件 |
| `ARRIVAL_TIMEOUT` | 在时限内未满足到达阈值 |
| `PLAN_INFEASIBLE` | 局部规划无可行轨迹 |
| `STALE_ACTION` | 下行目标超过可接受时滞 |
| `MAP_VERSION_GAP` | 目标关联的空间版本不可用或不连续 |
| `SAFETY_REJECTED` | L1/L2 或安全规则拒绝执行 |
| `SESSION_RESET` | 会话重置导致原目标失效 |

## 7. P0 实施顺序与验收

1. **运动基线（可与上行并行）**：完成 N4 到达与 N5 停栈复测，并回链 bag、ATE/RPE 或等价指标；P0-C 任务成功结论依赖其通过。
2. **P0-A 接出帧级增量**：从当前 SLAM Producer 的地图更新路径收集真实 `ADD`、有效 `UPDATE` 与 `EVICT`；确认更新函数能区分“收到点”和“状态改变”。
3. **P0-A 冻结事务边界并记录**：定义帧级去重、`session_id`、版本递增、`RESET` 与 `EVICT` 语义；建立不可变 DeltaBlock 与 Recorder，验证可重放且不明显影响 SLAM。
4. **P0-B 接通 x86 上行**：实现 `TokenSequence v0.1` Encoder/Decoder；先在干净网络验证编解码、版本连续、延迟、吞吐与资源。
5. **P0-C 接通下行闭环**：x86 VLN Adapter 产生 waypoint/ActionGroup；端侧关联空间版本与时间戳，经当前 Nav2 2D 和安全链执行并回传终态。
6. **P0-D 验证弱网安全**：无损闭环通过后逐轴增加带宽限制、延迟、jitter、丢包、断连与恢复；证明 L1/L2 可独立安全降级。

P0 闭环验收按三层进行：

| 层 | 通过条件 |
|---|---|
| 几何闭环 | 增量事件与版本可追溯；会话重置后旧链路可识别 |
| 运动闭环 | 目标可稳定转换为本地执行；到达、停栈行为有实测证据 |
| 弱网安全闭环 | 过期目标可校正或拒绝；断网时 L1/L2 独立工作 |
