# 个人岗位定位与空间智能基础设施发展规划

> 用途：内部岗位职责对齐、90 天工作规划、项目方案沟通与中长期职业发展。  
> 本文不是公司正式岗位说明书，也不替代 `ProjectState.md`、`40-验证/` 或产品架构 canonical 文档。  
> 保密：internal；涉及未 filed 的 Spatial Token、触发策略和专利细节时，必须回到专利敏感文档边界。

## 1. 文档结论

### 1.1 个人定位

**【设计定位】** 将个人岗位从“SLAM 算法工程师”逐步发展为：

> **SLAM 与空间智能基础设施方向的端边闭环负责人候选。**

当前不把“负责人”当作既成职级；是否正式承担 Owner 职责，需要由公司确认职责、资源、验收和授权。

### 1.2 对公司的价值

个人能力覆盖从底层感知到系统交付的连续链路：

```text
三维感知 / SLAM
  → 空间建模与坐标变换
  → 规划与任务执行
  → ROS 2 / DDS / 共享内存通信
  → Jetson / RK / x86 边缘部署
  → 多机器人协同与弱网验证
```

**【事实】** 个人经历材料显示，已有无人机巡检航线、Faster-LIO/Ego-Planner 部署、多机器人 3D 感知与协同建图、ROS 2 系统重构、边缘推理与实时视频链路经验。来源：`10-收集箱/papers/_inbox/曾欣宇.pdf`。

**【用户提供信息】** 2026-07-01 入职眸深，当前岗位为 SLAM 算法，月薪 18K；本项目方案前期已与余翀、陈涛沟通并获得认可。该信息尚未形成公司正式职责/薪酬书面确认。

### 1.3 与眸深的分工

```text
眸深：具身大脑 / 世界动作模型 / 跨本体智能
   ↑
   │ 几何锚定、检索上下文、现场状态回流
   │
个人主责方向：空间状态运行时 / Token 数据管线 / 弱网协同 / 本地安全执行接口
   ↑
   │
SLAM 前端：Super-LIO / FAST-LIO / 本体传感器适配
```

**【设计决策】** 对内外均采用“补链而非分权”的表达：不争夺眸深“具身大脑”定位，重点承担大脑所需的现场几何状态、端边数据流、任务执行反馈和验证资产。

## 3. 当前项目方案：ForkSpatialLink

### 3.1 项目层级

```text
motion
└── 上位无人协同系统工程

ForkSpatialLink
└── 空间状态与机器人任务执行中间件产品方向

Spatial Token
└── 当前核心空间数据契约

Go2 + Super-LIO/OctVox
└── 当前 P0 验证载体与首个 Producer
```

### 3.2 当前 P0 主链

```text
Go2 / Orin
  Super-LIO + OctVox
    → VoxelTransaction
    → TokenSequence v0.1
    → 现有 IP 数据面
    → x86 Token Decoder / VLN Adapter
    → waypoint / ActionGroup
    → Nav2 2D
    → Unitree 固件 / estop
    → 终态、失败原因、来源版本回传
```

**【事实】** 当前主链是 P0-A～P0-D：

1. P0-A：帧级增量事务与 Recorder；
2. P0-B：TokenSequence v0.1 与 Go2→x86 干净网络编解码；
3. P0-C：x86 VLN 最小闭环、端侧执行和结果回传；
4. P0-D：带宽、延迟、jitter、丢包、断连逐轴测试。

**【事实】** 当前 Go2 纯 Nav2 运动基线已有短距离真机证据：2 m、3 m 到达及行走中急停均有通过记录；静态障碍、WiFi 中断、ATE/RPE 与端边 Token 链路仍待补充。最新 SCAN-Planner hybrid 尚无对应验收记录。来源：`ProjectState.md`、`40-验证/BENCH-P0-Go2-MotionSLAM-基线.md`。

### 3.3 产品演进

```text
P0 软件 Runtime
      ↓
Go2 垂直验证 SKU
      ↓
通用 Spatial Token 硬件模组
      ↓
协议 SDK / Adapter 生态
      ↓
多机 Edge Gateway
```

Plugin、Skills、Rules、MCP 属于开发与运维控制面：

```text
只读探测
  → 兼容性报告

  → 隔离安装
  → 健康检查
  → 失败回退
```

它们不属于实时控制链，不能替代 Runtime、Nav2、固件避障或急停。

## 4. 岗位职责建议

### 4.1 基础职责：SLAM 算法工程师

- 负责 SLAM 前端、传感器、坐标系、时序与地图质量；
- 完成 Go2/Jetson 端的建图、定位和运动基线；
- 参与 P0-A 增量事件和 Recorder；
- 对定位误差、地图一致性、资源占用和异常恢复负责。

### 4.2 升级职责：SLAM 与空间 Runtime 方向

在公司确认后，职责可扩展为：

1. **空间状态 Owner**：定义 Producer 到下游的稳定状态边界；
2. **端边闭环 Owner**：推动 Go2→x86→Go2 的完整链路；
3. **模型接口 Owner**：将空间状态整理为模型可消费上下文；
4. **Benchmark Owner**：建立版本、带宽、延迟、恢复和任务成功指标；
5. **适配 Owner**：沉淀传感器、本体、ROS 2 和部署兼容矩阵；
6. **产品化接口人**：连接算法、模型、系统、硬件和客户现场；
7. **知识/IP 协作人**：将 measured 结果沉淀为内部能力卡、专利输入和脱敏材料。

### 4.3 职责边界

不建议个人无授权承担以下责任：

- 单独承诺通用多本体 production；
- 单独负责模型训练、数据采购和商业交付；
- 在没有测试资源时承诺弱网或多机指标；
- 未经专利/法务确认公开完整协议；
- 绕过本地规划器或固件安全链直接控制机器人。

这些事项需要公司指定产品、模型、系统、测试和法务负责人共同承担。

## 5. 个人短、中、长期规划

### 5.1 短期：0–90 天——从入职成员到可验证模块 Owner

**产品目标**

- 明确 Go2 验证套件的边界；
- 把当前方案收敛为可复现的 P0 证据包；
- 形成一次内部技术评审材料。

**技术目标**

| 周期 | 目标 | 证据 |
|---|---|---|
| 0–30 天 | 回链 N4/N5/N6 运动基线；补 NAV-2/NAV-4、bag/ATE；接出帧级事务与 Recorder | commit、bag、日志、失败码、hybrid 单独验收记录 |
| 31–60 天 | TokenSequence v0.1 编解码与 Go2→x86 干净网络首测 | 版本连续、吞吐、延迟、CPU/内存 |
| 61–90 天 | 固定场景完成上行→推理→下行→Nav2/L1→结果回传 | 端到端复现步骤与 Benchmark |

**学术/影响力目标**

- 建立 WeakNet Benchmark 初稿；
- 完成一次内部分享：`Communication-aware SLAM → 项目落地`；
- 只输出脱敏问题定义、指标和高层架构，不公开专利敏感细节。

**岗位评审节点**

> 建议在 60 天中期评审、90 天 P0-C 或等价阶段验收时，确认是否正式承担空间 Runtime/端边闭环 Owner 职责，并同步复议职级、薪酬、资源和激励。

### 5.2 中期：6–12 个月——从单机闭环到垂直产品能力

**产品**

- 完成 Go2 垂直验证 SKU；
- 形成隔离部署、诊断、升级/回退和现场复现包；
- 在单机 P0 证据成立后，评估 Swarm-SLAM、多机网关和弱网恢复；
- 评估第二种平台适配，验证契约是否真正前端/本体可替换。

**技术**

- 收敛 Spatial Token、Producer Adapter 和 Consumer Adapter；
- 完成 P0-D 弱网单变量结果；
- 建立 Map/Session/Version、终态和错误语义；
- 形成多机状态 merge、重定位和任务上下文检索的隔离原型；
- 评估 AsyncShield 时滞对齐，保持 Nav2/L1 回退。

**学术**

- 以 measured Benchmark 为基础准备 Workshop 或短文；
- 形成 `VoxelDiff / WeakNetSim / DDSBench` 等脱敏名片级成果；
- 继续围绕“通信感知的多机器人空间智能基础设施”对外交流。

### 5.3 长期：1–3 年——从垂直方案到基础设施方向

**产品演进**

```text
Go2 验证套件
  → 机器人垂直 SKU
  → Spatial Token Compute Module
  → Adapter / SDK 生态
  → 多机器人 Edge Gateway
  → Physical AI Infrastructure（长期愿景）
```

长期产品目标不是单独售卖 SLAM，而是让既有机器人通过统一空间状态和任务接口接入具身智能系统。

**技术演进**

- 前端可替换：LIO、VIO、RGB-D、第三方本体传感器；
- 状态可扩展：几何、语义、动态、不确定性和任务相关空间记忆；
- 通信可测：带宽、延迟、jitter、丢包、断连、恢复；
- 执行可回退：语义层失效不影响本地规划和安全链；
- 控制面可自动化：Manifest、兼容矩阵、受控部署、诊断与 MCP；
- 多机可协同：空间状态 merge、任务相关同步和异构平台接入。

**学术演进**

```text
工程闭环
  → WeakNet Benchmark
  → 关键帧 / 增量空间表示
  → 通信感知多机协同
  → Shared Spatial Belief
  → 动作条件世界模型（长期挑战）
```

不把尚未完成的 Shared Spatial Belief 或动作条件 World Model 写成当前成果。

## 6. 产品—技术—学术三线关系

| 线 | 当前问题 | 当前产出 | 长期价值 |
|---|---|---|---|
| 产品 | 眸深大脑如何稳定获得现场空间状态并驱动机器人 | Go2 验证、Runtime、端边闭环 | 垂直 SKU、模组、网关 |
| 技术 | 如何让空间状态版本化、可传输、可回放、可安全执行 | VoxelTransaction、TokenSequence、Adapter、Benchmark | Spatial Runtime / SDK |
| 学术 | 弱网条件下多机器人如何共享任务相关空间信念 | WeakNet 指标、增量表示、通信感知协同 | Workshop、论文、研究方向 |

**【设计原则】** 一件工程工作尽量形成“一鱼三吃”：

```text
VoxelDiff / 增量空间状态
  ├─ 产品：减少数据量，支持弱网部署
  ├─ 技术：降低 CPU/传输成本，形成可回放契约
  └─ 学术：形成通信感知空间协同问题与 Benchmark
```

### 7.3 待遇谈判原则

**【用户提供信息】** 当前月薪为 18K；以下不是市场定价结论，而是职责升级后的谈判锚点：

- 仅承担 SLAM 算法执行：保持当前岗位边界；
- 承担空间 Runtime/端边闭环模块 Owner：建议约定 60–90 天复议；
