## 1. 路线判断：为什么这条线值得长期押注

### 1.1 核心优势——难以被 Foundation Model 直接替代

**【推断】** 无论底层前端如何演进——Super-LIO、神经 SLAM、某种机器人基础模型——**多机器人系统级约束不会消失**：

- 有限带宽
- 通信不稳定（丢包、延迟、断连）
- 异构平台（传感器、算力、运动学）
- 任务协同与调度

因此下列能力更像**长期存在的基础设施层**，而非可被单一「大模型」整包替换的模块：

| 能力 | 角色 |
|---|---|
| KeyFrame / VoxelDiff 增量协议 | 跨机共享「空间里有什么、变了吗」的稳定契约 |
| 通信感知调度 | 在带宽/QoS 约束下决定「谁发什么、何时发」 |
| Weak Network Benchmark | 统一尺子：版本、算法、中间件均可对比 |

**【事实】** 仓内竞品分层已将 motion 规划在 **L4：弱网运行时几何协议 + 协同网关**（`03-技术分析/竞品与生态对标_*.md` §2）；眸深等在 **L3 具身大脑**。

### 1.2 与 FieldAI 的分工——互补而非竞争

| 维度 | FieldAI（及同类整脑自治） | 本主线（motion L4） |
|---|---|---|
| 核心问题 | 单个机器人如何在未知环境中**自主决策**？ | 多个机器人如何在真实通信约束下形成**高效、可靠、可扩展的群体智能**？ |
| 典型产出 | Belief World Model、单机探索与规划 | 增量空间协议、弱网评测、多机 merge、通信感知协同 |
| 关系 | 每个机器人的「大脑」 | 多个大脑之间的「神经网络与协作协议」——共享知识、协同推理、高效通信 |

**【推断】** 若未来 FieldAI 式 Belief World Model 成为单机标配，本线价值**上升而非下降**：大脑越强，跨机同步与通信效率越成为瓶颈。

### 1.3 与眸深 / 公司产品的分工

**【事实】** 竞品文档 §7.3：对眸深为**补链而非分权**——几何底座与现场协同，品牌不抢「大脑」。

```text
眸深 / L3 具身大脑
    ↑ 几何锚定 / 检索上下文 / 多机回流
motion = L2～L3 之间的「运行时数据管线」+ L4 弱网协同网关
    ↑ 可接
L1 前端（Super-LIO / Odin1 / 本体雷达 …）
```

**双轨对外口径（已拍板，执行中）：**

- **对公司老板 / 客户 / 商务**：弱网多机协同网关、协同中间件、技术沉淀（招聘 / 商务 / 品牌）
- **对导师 / 会议 / 个人品牌**：Communication-aware Multi-Robot Spatial Intelligence Infrastructure

## 3. 学术生态位（Academic Niche）

### 3.1 让别人记住你的一句话

> **那个做 Communication-aware Multi-Robot Spatial Intelligence Infrastructure 的人。**

**不是**「做 SLAM 的」，**不是**「做调度大脑的」，**不是**「做世界模型的」。

所有 GitHub 项目名、PPT、博客、论文、分享标题**默认带同一主题**，子题可换，主品牌不换。

### 3.2 技术主线（与公司项目对齐）

```text
Multi-Robot SLAM / 协同网关
        ↓
KeyFrame + SpatialChunk / VoxelDiff（增量空间契约）
        ↓
Weak Network（丢包 / 延迟 / 带宽 / 断连）
        ↓
Communication-aware Collaboration（调度 + 可选 RL 策略层）
        ↓
Weak Network Collaborative SLAM Benchmark（统一评测）
```

### 3.3 论文 / 支线收束（避免叙事分叉）

| 条目 | 角色 | 时间 |
|---|---|---|
| **P3 关键帧压缩 / 通信调度** | **名片论文主轴**；与 VoxelDiff、弱网 Bench 最近 | 专利 filed 后 → Workshop / 短文优先 |
| **WeakNet Benchmark** | 影响力 + 学术入口；可先占「问题 + 指标」 | **2026 优先** |
| **P1 弱网协同世界模型** | 中期叙事；几何锚定 + 多机共享 | 主专利 filed 后展开 |
| **P2 异构跨楼层** | 明年产品线论文壳 | P1 平台后 |
| **RL 支线** | 通信预算感知协同**策略层**；不另立品牌 | 与主规划并行，不阻塞 P0 |
| **3D 空间记忆瞄点** | 服务眸深/L3 接口；非今年主战场 | 非 P0 WBS |

**【铁律】** 今年不试图同时讲「世界模型 + RL + 3D 记忆 + 弱网协议」四个独立故事。

## 4. 时间分配：50% · 30% · 20%

> **注意**：不是三条平行线各做各的，而是 **50% 为唯一事实来源**，30% 从主线**抽离、脱敏、包装**，20% **围绕同一句话**连接导师与同行。

### 4.1 50% — 公司主线（产品 + 研究素材）

**目标**：用项目验证 KeyFrame/VoxelDiff、弱网协同、ROS 2 通信优化，做成可落地产品能力。

**对齐仓内 P0**（`01-工作计划/多机器人协同_详细技术与科研规划.md` §9）：

| 阶段 | 内容 | 一鱼三吃 |
|---|---|---|
| M0 | Go2 单机 commit/bag + P0 Benchmark 首组 | 工程闭环；影响力：首组数据 |
| M1–M2 | Swarm-SLAM 仿真 Gate | 准入决策；WeakNet 仿真场景 |
| M3–M4 | 双机 + x86 网关 + WiFi + 中间件 | 商业：省带宽；工程：降 CPU/传输；研究：增量表示 |
| 指标 | Weak Network Collaborative SLAM Bench | 公司：版本对比；学术：评测论文壳 |

**占用资源**：真机、仿真、网关开发为主；**不**为学术单独开 Isaac / 全量 3DGS / FieldAI 级整脑。

## 5. 与公司沟通：把自己定位成「技术桥梁」

### 5.1 错误话术 vs 正确话术

| ❌ 不要说 | ✅ 要说 |
|---|---|
| 「我想搞论文 / 申请研究」 | 「我想把弱网多机协同这块做成**可展示、可评测、可复用**的技术资产」 |
| 「论文是 KPI」 | 「白皮书、Benchmark、Demo、对外分享 → 服务**招聘、商务、品牌**；论文是副产品」 |

### 5.2 可主动承担的三件事

#### ① 技术分享（每月一次）

- **主题示例**：Communication-aware SLAM；FieldAI 与我们 L4 的分工；多机器人 Spatial Intelligence Infrastructure
- **形式**：不是念论文，而是 **论文 → 我们项目怎么落**
- **效果**：老板感知为「提升整个团队」，而非个人脱产

#### ② Reading Group（每周 ~40 分钟）

- **来源**：ICRA / RSS / CoRL 最新稿
- **讨论焦点**：哪些能放进产品？哪些只是学术玩具？
- **效果**：低占用、高可见度；易建立「带团队看方向」的形象

#### ③ Benchmark 负责人（强烈建议）

- **名称**：Weak Network Collaborative SLAM Benchmark（弱网协同 SLAM 评测）
- **老板问「有什么用？」** → 答：

```text
以后所有优化都有统一测试：
  Packet Loss → Latency → Bandwidth → DDS QoS → Map Accuracy / SR / 断连恢复
每个版本、每种中间件、每种压缩策略都能对比。
```

- **落盘**：扩展 `40-验证/P0-Benchmark-模板.md` → 新建 `P1-WeakNet-Collab` 系列

### 5.3 一鱼三吃示例（学术与商业绑定）

以 **VoxelDiff / 增量 SpatialChunk** 为例：

| 维度 | 价值 |
|---|---|
| **商业** | 节省带宽 → 弱网场景可交付 |
| **工程** | 降 CPU / 降传输 → 边端可跑 |
| **论文** | Incremental Spatial Representation for Multi-Robot C-SLAM（P3 方向） |

**禁止**论文一条线、商业一条线、各做各的。
