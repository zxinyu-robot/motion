# 社交导航支线：POMDP + ESN + PPO-Lagrangian「绕行 vs 停等」

> **定位**：单机动态行人场景下的**智能增强**支线（拟人绕行 / 停等 / 减速），**不纳入**产品 P0 WBS。  
> **与主线关系**：挂在「VLA/ActionGroup → 本地规划 → L1」之间的可选元控制层；不替代 Super-LIO、FSLP/FST、Nav2/MPPI、固件兜底。  
> **与通信 MARL 支线**：`多机器人协同_RL支线计划.md` 管「何时共享/谁做任务」；本文件管「遇人绕还是等」——**叙事分开，勿合并**。  
> **保密**：internal；PPO-Lagrangian / CMDP 类接口与 AsyncShield 同源形态处标为**他人方法/现有技术**，不写入自有独权。

---

## 1. 一句话

POMDP 作为「部分可观测环境下如何更新信念并选动作」的形式化框架；ESN 仅把过去数秒的行人和机器人时序压缩为动态隐状态；PPO-Lagrangian 在社交奖励 + 硬安全约束下学「绕 / 等 / 缓」；底层仍走轨迹优化与 Sport/Safety 急停。人类社交规范靠「真实人类导航数据预训练 + 社交奖励 + 硬约束」注入，**不是** ESN 自发涌现。

---

## 2. 启动门闩（优先级）

**【事实】** 当前 Go2 纯 Nav2 基线为 Super-LIO + SHM/哈希 costmap + Nav2 2D（MPPI）；2 m / 3 m 到达与行走中急停已有通过记录。静态障碍、WiFi 中断、端边 Token 链路仍待验证；最新 SCAN-Planner hybrid 尚无验收记录。来源：`BENCH-P0-Go2-MotionSLAM-基线.md`、`ForkSpatialLink-实现方向_含AsyncShield对齐.md`。

**【设计决策】同时满足前不要开阶段 2+：**

1. 端侧到达或至少 planner↔哈希地图 + Go2 偏航可验收；  
2. FSLP 链路通、上行测速与格式选型有结论；  
3. 痛点已明确是「动态行人不够拟人」，而非「到不了点 / 传不上图」。

门闩未到：最多做 **§7 阶段 1 离线摸底**（≤调研量级），不开 Isaac + PPO 战役。

## 3. 在 ForkSpatialLink 栈中的位置

```text
VLA / ActionGroup (point, prefer-yaw)
        ↓
[可选] 时滞对齐（AsyncShield 白盒 SE(2)；P0.5）
        ↓
[可选] 社交元控制（本支线：绕行 / 停等 / 减速）  ← P1+
        ↓
本地规划（Nav2 MPPI / 后续 MPC；哈希地图适配）
        ↓
Sport SDK + Safety Monitor / 固件 L1
```

| 层 | 主线已有 | 本支线 |
|----|----------|--------|
| 上行几何 | Super-LIO → FST/FSLP | 不替代；行人状态另路，勿塞进 Token 独权 |
| 下行异步 | 时滞对齐插件位 | 可同「元控制」插槽，问题不同（延迟 vs 社交） |
| 局部规划 | MPPI + 哈希/costmap | ESN-MPC 为之上/之后社交层 |
| 兜底 | Sport + estop | **必须保留** |

### 3.1 与项目闭环的统一表达【设计决策】

```text
真实环境
  → 观测 o_t
      ├─ PoseStream + VoxelTransaction / MapVersion
      ├─ DynamicActorStream（行人位置、速度、朝向及置信度）
      ├─ NeighborEvent（后续多机通信支线）
      └─ ExecutionResult（终态、失败码、安全介入）
  → 显式状态 x_t + ESN 动态隐状态 h_t
  → Belief Adapter 形成规划输入 b_t
  → VLN / 规则 / 社交元控制 / 本地规划
  → ActionGroup / waypoint
  → 时滞检查 + Nav2/局部规划 + L1 安全兜底
  → 新观测与执行结果反馈
```

- **POMDP 是问题描述与决策框架，不新增一个必须部署的“POMDP 节点”**。它用于明确状态、观测、动作、转移、奖励与不确定性。
- **显式状态**由位姿、地图事务、会话/版本和任务结果组成，必须可记录、可重放、可归因。
- **隐式状态** `h_t` 由 ESN 对短时动态历史编码，只能辅助预测和决策，不得替代空间版本、失败码或安全状态。
- `h_t` 只有经过概率校准或明确的 Belief Adapter 后，才可称为 POMDP 的近似信念表示；不能把任意 ESN 隐向量直接宣称为概率信念状态。
- 通信事件和执行结果都是下一轮观测的一部分；断网、ESN 失效或置信度不足时，系统退回现有显式状态、规则/规划器和 L1/L2 安全链。

### 3.2 插件边界【设计决策】

为避免侵入当前 P0，后续原型只通过三个旁路契约接入：

```text
DynamicActorStream → ESN Belief Encoder
NeighborEvent      → Belief Fusion
ExecutionResult    → Belief / Planner Feedback
```

输出统一收敛为已有的 `waypoint/ActionGroup` 或局部规划约束，不允许 ESN/PPO 直接发布 `/cmd_vel`。具体字段、频率、时序与 ROS 接口均为【待补充】，须在门闩通过后单独冻结。

## 4. 推荐分层架构【方案草案】

```text
┌─ 感知层 ─────────────────────────────┐
│ LiDAR 点云 + 行人检测 + 速度估计       │
│ 提取: 位置、速度、朝向、类别           │
└──────────────────────────────────────┘
                 ↓ (时序窗口 T=2~3s)
┌─ ESN 信念编码器 ────────────────────┐
│ 储层 N=300~500, ρ=0.85~0.95         │
│ 输入: 机器人状态 + 行人状态历史        │
│ 输出: 动态隐状态 h_t ∈ R^64            │
│ 预训练: MuSoHu / GazeNav 类读出层      │
│        行为预测（人类数据，可迁移）    │
└──────────────────────────────────────┘
                 ↓
┌─ PPO-Lagrangian 元控制器 ───────────┐
│ 状态: [显式状态, h_t, VLA subgoal]     │
│ 动作: 离散[绕行/停等/减速/加速]       │
│       或连续[Δx, Δy, v_pref]         │
│ 奖励: R_progress / R_social(SCP) / R_smooth │
│ 约束: C_safety = min_dist ≥ 0.6m    │
└──────────────────────────────────────┘
                 ↓
┌─ ESN-MPC 轨迹优化器 ────────────────┐
│ 基于 ESN 人类动力学预测 → 可执行轨迹   │
└──────────────────────────────────────┘
                 ↓
┌─ Sport SDK + Safety Monitor ────────┐
│ 轨迹跟踪 + 硬急停兜底                 │
└──────────────────────────────────────┘
```

### 4.1 关键设计点

| 点 | 说明 |
|----|------|
| ESN 预训练 | MuSoHu / GazeNav 等真实人类导航数据；任务「过去 2s → 未来 1s 位置」；**不依赖 Go2 真机** |
| WAIT 显式动作 | 零速保持；前方轨迹交汇且意图不确定时优先停等，避免强行绕行 |
| SCP 类奖励 | 借鉴 Falcon「轨迹阻碍惩罚」：与行人未来轨迹重叠给负奖励 → 倾向「等人先过」 |
| HRSC 类朝向项 | 行人正面朝向加大避让；打电话/低头等【待补充检测】可加大停等倾向 |
| 硬约束 | `min_dist_to_human ≥ 0.6m`（阈值可标定）；学习失败时规则/急停接管 |

### 4.2 奖励与约束（草案）

- \( R_{progress} = -\|p - p_{subgoal}\| \)  
- \( R_{social} = -SCP(h_t) \)（Falcon 式轨迹阻碍）  
- \( R_{smooth} = -\|a_t - a_{t-1}\| \)  
- 约束：\( C_{safety}: \min_dist \ge 0.6\,\mathrm{m} \)（Lagrangian / 屏蔽非法动作）

**【待补充】** SCP/HRSC 的具体公式与文献条目入 `04-文献阅读/notes/07-规划-控制-RL/` 后回链。

## 5. ESN 的替换边界及相对 LSTM/GRU 的主张【推断】

这里的“替换”是替换或补充 **LSTM/GRU 时序编码模块**，不是替换单个神经元，也不是替换 SLAM、Spatial Token、VLN、规划器或安全控制器。ESN 是否值得进入后续主线，只由同数据、同场景、同接口的单变量对照裁决。

| 点 | 主张 | 备注 |
|----|------|------|
| 训练成本 | 只训读出层（岭回归），无 BPTT | 利好 Jetson 在线自适应【待测】 |
| 梯度 | 储层固定，无消失/爆炸 | — |
| 记忆窗口 | ρ、泄漏率 α 可调；绕/等常需 2–4s，ρ≈0.9 | 需扫参验证 |
| 噪声 | 储层低通，对点云噪声相对钝感 | 相对 MLP/LSTM，**【待测】** Sim2Real |

## 6. 必须清醒的三个局限

1. **ESN 不理解社交规范**：只是统计记忆；分布外（轮椅、异常行为）可能编码异常。  
2. **数据质量定上限**：仿真 ORCA 轨迹易学成机械化人类；预训练须真实人类导航数据。  
3. **安全不能只靠学习**：突然冲出、儿童、宠物 → 历史窗口来不及 → **Sport + Safety Monitor 硬兜底**（与 AsyncShield / 端侧 L1 原则一致）。
