## 3. 🟡 黄色区：部分覆盖，须组合创新

### 3.1 端边分层存储 / 按需分发

**已有语境**：车路协同 HD Map（基础层车端 / 细节层路侧）、V2I/V2V 预存、按区域元素增量更新、NDS 分层分块。

**缺口【推断】**：少见把 **SLAM 产出的多维 layer** 与 **按消费者投影（规划/模型）** 绑在机器人端边链路上（而非车端预装 vs 路侧粗二分）。

**组合方向**：几何/语义/物体/拓扑 **分别路由** + 版本对齐 + 规划投影（接 C-b/C-c）。

### 3.2 多机器人分布式增量融合

**已有**：特征点局部图增量、关键帧位姿图合并、局部→全局几何融合。

**缺口【推断】**：多机同时写同一区域时的 **乐观并发、冲突检测、回滚/仲裁** 版本层，公开专利中少见完整串案（几何对齐专利多，版本一致性专利少）。

**归属建议**：C-h / 后置；勿塞进本批 Ca。

### 3.3 空间信息服务化 / 代理鉴权

**已有**：如 CN108280178A（SOA + CSW + 代理权限）类 GIS 治理。【待补充】核对。

**缺口【推断】**：与 **SLAM 地图增量流的 consumer-driven contract** 未结合。

## 4. 🟢 绿色区：可重点布局（候选，非已证实空白）

> 【待补充】下列「未见完整公开」均基于本轮检索；英文库已出现 digest/hash 版本链、NNG delta 等，**绿色须收窄表述**，禁止写成「世界上首次 content-addressing」。

### 4.1 机会 A：多维 Layer 增量的版本化封装 + 不可变组合（→ C-b 核心独权1）

**相对红区差异【推断】**：  
南湖写「各层单独更新」；NNG 写「tile/layer delta + 版本确认」；组合缺口更可能在：

- 面向 **机器人 SLAM 旁路几何主源** 的分层局部增量信封；  
- 与 **三维多层综合规划投影 / 模型按层取用** 绑定；  
- 显式 `base_version → new_version` 组合语义（是否 content-hash / Merkle 仅作实施例，**不宜当唯一区别特征**——已有 US11423062、DE102022000272B3 等 digest/hash 近邻）。

**【设计决策·布局抓手】**（交底级，非定稿独权）  
增量包 = 信封 + 载荷引用；信封含会话/空间版本、affected_layers、coord_anchor、生产者校验；组合为可回放事务。完整字段与伪码申请前勿公开。

### 4.2 机会 B：LayerDelta 信封作为独立保护对象（→ C-b 核心；与独权2 compose 组合）

**抓手【设计决策】**：以 `layer_id + region + change_type + payload_ref + deps` 为组织单元；`change_type` 含 ADD/UPDATE/EVICT/RESET（及可选 MERGE）；`deps` 支持乱序重组。

**注意**：局部子图/瓦片/PSF 已有专利——独权须钉在 **机器人多维 layer 增量契约语义**，勿只写「又一种差分记录」。

### 4.3 机会 C：AccessTicket / 消费契约驱动的按需投影（→ 卫星 C-c）

**相对高德【推断】**：高德令牌 = **购买范围商业授权**；目标升级为 **技术订阅契约**：allowed_layers / allowed_regions / version_cap /（可选）QoS，服务端按契约 **lazy materialization**。

**划界必须写清**：鉴权购图 Token ≠ 空间版本消费契约。

### 4.4 机会 D：多机并发写的版本冲突仲裁（→ 卫星 C-h）

**抓手【设计决策】**：多生产者提交 LayerDelta → 基于 base_version 检测冲突 → 重对齐或策略仲裁；MRF/异常回环等仅从属或另案。

### 4.5 机会 E：契约测试 / 版本兼容矩阵（从属或商业秘密）

Producer-driven contract test for LayerDelta schema——适合从属或内部规范，**不必单独立案**。
