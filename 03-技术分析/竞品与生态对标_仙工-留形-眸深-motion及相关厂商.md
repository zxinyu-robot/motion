## 1. 一句话结论


| 对象                  | 产业层                              | 与 motion 的默认关系                        |
| ------------------- | -------------------------------- | ------------------------------------- |
| **仙工 SEER**         | 工业造车控制器 + 整厂调度                   | **产品侧主对标**（免预建图 / 弱网 / 语义调度）          |
| **留形 Odin1**        | 边端空间感知与闭源 MindSLAM 模组            | **感知前端竞品或可选供应商**，非同层调度网关              |
| **留形 MindCloud**    | 空间数据平台 / Real2Sim / 标注 /「多机记忆共享」 | **L3 数据管线叙事上最近的国内对手**；应用运行时弱网指标错位     |
| **眸深 Motion Brain** | 原生具身大脑（世界动作模型）                   | **优先视为母体/上层生态**；motion 补数据管线 + 现场协同底座 |
| **motion（规划）**      | L3 配套数据管线 × L4 弱网协同网关            | 稀缺组合位；忌做成第二 MindCloud 或第二 SRC         |


**【核心判断】**  
公开市场上多数厂商在「离线空间资产 / Real2Sim」与「运行时自治或物流调度」之间二选一；**「在线几何契约 + 弱网多机 + 喂具身大脑」**仍相对稀缺。motion 应抢后者，而不是用 3DGS 保真度去硬刚其域/留形。

## 2. 产业分层模型（全文统一坐标系）

为避免「空间记忆」「世界模型」「调度大脑」等词撞车，本文固定使用下列分层。编号仅用于本文，不等于公司组织架构。


| 层      | 名称                     | 卖什么                         | 代表                                       |
| ------ | ---------------------- | --------------------------- | ---------------------------------------- |
| **L0** | 工业调度与造车控制              | 预建图、SRC 类控制器、整厂任务/仓配        | 仙工 SRC / M4、部分 AMR 调度商                   |
| **L1** | 边端空间感知 / 海马体模组         | 传感 +（常闭源）SLAM，吐位姿/点云        | 留形 Odin1；传统 LiDAR+LIO 模组                 |
| **L2** | 空间数据平台 / Real2Sim / 标注 | 重建、3DGS、孪生、单体化、训练数据、记忆库     | 留形 MindCloud、其域、如视、DreamVu 等             |
| **L3** | 具身大脑                   | 动作生成、世界模型、VLA、持续学习          | 眸深、极佳视界、蚂蚁灵波等                            |
| **L4** | 弱网运行时几何协议 + 协同网关       | 增量 Token、边云分层、断网降级、多机 merge | **motion 规划主战场**；国际近邻 FieldAI / Roam（半边） |


### 2.1 按工作假设下的 motion 定位

```text
眸深（L3 大脑）
    ↑ 几何锚定 / 检索上下文 / 多机回流
motion = L2～L3 之间的「运行时数据管线」
       + L4 弱网协同网关
    ↑ 可接
L1 前端（Odin1 / Super-LIO / 本体雷达 …）
```

**【推断】**  
「L3 同能力的数据管线」≠ 再训练一个 HL3DWM；而是指：**为 L3 大脑提供同量级空间理解所需的数据与现场同步能力**（增量几何、图索引、多机共享、弱网可达）。

### 2.2 「多机记忆共享」语义消歧（强制）


| 含义 A（常见于 MindCloud 类）               | 含义 B（motion 规划）                                       |
| ----------------------------------- | ----------------------------------------------------- |
| 离线或准离线：扫描/重建后形成可复用「空间回忆」资产，供多机或训练复用 | 在线：弱网下实时/准实时交换 KeyFrame、SpatialChunk/VoxelDiff，断网本地降级 |
| 指标多为重建精度、标注效率、孪生保真                  | 指标为带宽 KB/s、关键帧延迟、任务成功率、断连恢复、碰撞/兜底次数                   |
| 主要服务训练与数字孪生                         | 主要服务现场协同与大脑在线推理                                       |


**【判断】** 对外若只说「多机记忆共享」而不分 A/B，评审与客户会把 motion 听成 MindCloud。

## 3. 四路线详解

### 3.1 仙工智能（SEER）—— L0 工业调度

#### 3.1.1 公开定位【事实】

- 以 **SRC 系列核心控制器** + 数字化软件（如 Roboshop 实施工具、M4 智能物流管理系统等）服务 AMR / 叉车造车与整厂调度。  
- SRC 提供地图构建、定位导航、模型编辑等；可扩展控制充电桩、自动门、电梯等工厂基础设施。  
- 产品线覆盖入门级至安全型（如 SRC-3000FS 等安全认证叙事）。  
- 来源：`seer-robotics.ai` 控制器与软件页。

#### 3.1.2 仓内对标口径【事实】

来源：`01-工作计划/多机器人协同_详细技术与科研规划.md` §1、`工作计划.md`、`02-架构设计/SLAM-Token弱网中间件-汇报材料.md` §2.2 / §5.3。


| 仙工软肋（仓内表述）        | motion 目标差异化                   |
| ----------------- | ------------------------------ |
| 需要**预先建图**        | **免预先建图**（前端在线 + 网关离线增量建图）     |
| 依赖较稳定网络与静态地图      | **弱网原生**：Token 流 + 断网本地降级      |
| 同平面 + RPC 几何调度    | 瞄准异构平面/异构本体 + VLA **语义调度**原语   |
| 任务原语偏「去 A 取货→B 放」 | 「找不知道在哪的杯子」类语义任务需协同视角/地图 merge |


> 注：「免预先建图」在仓内定义为：任务开始前无需人工制作全局地图，系统仍在运行时在线增量建图。【事实·主规划 §1】

#### 3.1.3 仙工相对强弱【综合】


| 强                     | 弱 / 非主战场                    |
| --------------------- | --------------------------- |
| 造车 + 实施工具 + 整厂调度交付链成熟 | 弱网 / 无 GPS / 足式人形异构非主叙事     |
| 功能安全与工业接口             | 语义任务与增量 3D Token 非产品核心      |
| 集成商路径短、车型库丰富          | 世界模型偏静态几何站点【仓内推断口径；对外需实测校准】 |


#### 3.1.4 对 motion 的含义

- **叙事上**对标「调度大脑」品类，但**产品上不做第二 SRC**。  
- 差异化三连击保持：免预建图、弱网、语义/异构；今年 MVP 仍是同层办公场景验证【事实·主规划】。

### 3.2 留形科技（Manifold）—— L1 Odin1 + L2 MindCloud

留形必须按**双星产品**理解，不能只比 Odin1 硬件。

#### 3.2.1 Odin1：空间记忆模组（L1）【事实】


| 项         | 公开信息                                                                     |
| --------- | ------------------------------------------------------------------------ |
| 定位        | 「全球首款空间记忆模组」；LiDAR + RGB + IMU + 内置 MindSLAM                             |
| 输出        | 真彩/原始点云、RGB、IMU、高频位姿                                                     |
| 宣称精度      | 内置 SLAM 定位 ±5 cm + 1%（官网参数表）                                             |
| 形态        | 约 280 g；IP66；额定约 11 W                                                    |
| 软件        | SDK & ROS；Nav-Stack 示例以 Unitree Go2 + ROS1 Noetic 为主                     |
| Nav-Stack | 开源导航/避障/YOLO 语义导航/VLM 描述；**SLAM 在模组内未开源**                                |
| 来源        | manifoldtech.cn / 3dmanifold.com；GitHub `ManifoldTechLtd/Odin-Nav-Stack` |


**【判断】** Odin1 落在汇报材料所写「市面有 LiDAR + 内置 LIO、输出 odom/cloud」的玩家槽位（`SLAM-Token弱网中间件-汇报材料.md` §2.1），**不是**「Spatial Token → VLA/调度」中间层。

#### 3.2.2 MindCloud：智能空间数据平台（L2）【事实·综合】

WRC 展商材料与官网/大会报道将闭环表述为：Odin1（及 Pocket 等）采集 → MindCloud 优化/标注/重建 → 可复用「空间回忆」→ 多机器人记忆共享与具身模型训练。

**已公开能力范围（会话整理 + 公开材料交叉）：**


| 能力                  | 说明                                                    |
| ------------------- | ----------------------------------------------------- |
| 原始点云 → 厘米级 3D 模型    | 扫描:重建效率公开口径约 **10:1**                                 |
| 数据自动单体化、2D→3D 分割    | 语义资产生产                                                |
| 高保真 3D 高斯泼溅（3DGS）渲染 | 孪生/可视化表达                                              |
| 大规模数字孪生环境构建         | Real2Sim 方向                                           |
| **多机器人记忆共享**        | 见 §2.2 含义 A；协议粒度【待核实】                                 |
| 高效率低成本数据标注工具        | 服务 VLA 等具身模型训练                                        |
| 桌面端与移动端多层次空间数据管理    | MindCloud Studio / Go / Render / MindCloudX.AI 等工具链叙事 |


**定价：** 完全封闭。【事实·会话侧】符合平台型 SaaS/私有化议价常见形态。

#### 3.2.3 留形产品矩阵关系【事实】

WRC 展商介绍还包含 **Pocket2** 等多模态采集设备，与 Odin1、MindCloud 组成「前端感知 → 后端训练/孪生」闭环。

#### 3.2.4 留形 vs motion


| 维度   | 留形                | motion（规划）                        |
| ---- | ----------------- | --------------------------------- |
| 硬件模组 | **传感+闭源 SLAM 一体** | **计算/协议一体**（Orin NX Token 盒；传感外置） |
| 平台重心 | MindCloud 资产与训练场  | 运行时 Token + 协同网关                  |
| 多机   | 记忆共享（偏资产）         | 弱网增量同步 + 断网安全                     |
| 成熟度  | 可购硬件 + 展会/客户故事    | 统筹 proposal，缺 measured            |
| 定价   | MindCloud 封闭      | 规划：盒子+固件 → 协议 SDK → 云服务           |


**【竞合建议】**  
客户已买 Odin1 时，合理路径是：Odin 作 L1 前端 → Adapter 输出 KeyFrame/VoxelDiff → motion 网关；而不是二选一替换。【推断】

### 3.3 眸深智能（Motion Brain）—— L3 具身大脑

#### 3.3.1 公开定位【事实】

- 成立约 2025；联合创始人含穆泽林、复旦教授**陈涛**、原英特尔中国研究院首席科学家张益民等（公开报道）。  
- 定位：**原生范式通用具身大脑**，「一脑多形」；英文 MOTION BRAIN。  
- 技术体系：**世界动作模型（World Motion Model）**。  
- 产品/里程碑叙事包括：MotionGPT 系列、T²MB（持续进化/离线部署提升叙事）、HL3DWM（类人思维方式的三维世界模型）。  
- 融资：公开报道含天使追加、Pre-A 约 3 亿元等。  
- 陈涛公开观点：产业将趋于分工，眸深聚焦世界动作模型核心层，赋能本体与集成商；强调端侧轻量化与跨本体。【事实·36氪等】

#### 3.3.2 与「空间记忆 / 数据」的关系【事实 + 推断】

- HL3DWM 公开描述含：物体感知图像检索（OIR）、环境感知信息聚合（EIA），结合点云全局关系与图像细节完成 3D 视觉-语言类任务——即**模型侧空间记忆与检索**。  
- 数据策略公开叙事强调：大量互联网视频预训练 + 较少真机微调、数据飞轮、格式统一等。  
- 早期报道提及订单有「数据生成器」收入成分。【事实·报道】  
- 融资用途含「全链路工具链完善」。【事实·融资稿】

**【推断】** 眸深需要配套的**现场几何回流与多机空间上下文管线**，但公开产品并不等同于留形 MindCloud 那种 3DGS 资产云；这正是 motion 工作假设的插入点。

#### 3.3.3 眸深 vs MindCloud vs motion


|        | 眸深       | MindCloud | motion（工作假设）              |
| ------ | -------- | --------- | ------------------------- |
| 货架     | L3 大脑    | L2 资产平台   | L2～L3 运行时数据管线 + L4 网关     |
| 「空间记忆」 | 模型内检索与推理 | 资产库「空间回忆」 | 版本化增量几何 + 弱网同步            |
| 对 VLA  | 训练与部署大脑  | 提供训练数据/孪生 | 在线喂几何 Token / Graph；训练可回流 |
| 默认关系   | 母体/上层    | 数据侧竞品或外采  | 眸深补链产品                    |


**【组织注意】** motion 主规划对齐陈涛/余翀方向【事实·主规划】。对外是否宣称「眸深 motion 产品线」【待补充】。对内话术建议避免与 HL3DWM 抢「空间记忆」商标式用语，改用「几何 Token / 协同网关 / 数据回流」。

### 3.4 motion —— L3 配套数据管线 × L4 弱网协同

#### 3.4.1 仓内产品定位【事实】

来源：主规划 §1、汇报材料、技术方案。

- 一句话：面向弱网、无 GPS 的**边缘智能协同网关**——开箱即用的「调度大脑」控制器（对标仙工）。  
- 形态：**模组 + 网关**；连 IP 即用。  
- 协议层：前端无关的 `KeyFrame + SpatialChunk/VoxelDiff`（草案，未冻结）。  
- P0：Go2 单机基线 → Swarm-SLAM 仿真 Gate →（通过后）双机 + x86 网关 + WiFi。  
- 原则：VLA 不上狗；VLA 不直发 `/cmd_vel`；L1 固件避障 + L2 规划兜底。

#### 3.4.2 产品切片【事实】


| 切片             | 形态                                         | 卖点                    |
| -------------- | ------------------------------------------ | --------------------- |
| A 边缘 Token 盒   | Orin NX + Local Map Adapter + tokenizer 固件 | 输出 diff token，下游免再体素化 |
| B Token + 局部规划 | A + ego-planner                            | 无 VLA 也能探索；接 VLA 升级语义 |
| C 协议 + SDK     | `libspatial_tokenizer` + schema            | 前端无关协议与 Adapter       |


商业路径：卖盒子（硬件+固件）→ 卖协议（SDK+生态）→ 云服务（VLA 托管/私有化）。【事实·汇报 §2.4】

#### 3.4.3 硬件形态结论【事实·规划 / 待补充·工程】

**最终硬件不是 Odin 式传感模组，而是：**


| 件    | 规划硬件                                                        | 角色                  |
| ---- | ----------------------------------------------------------- | ------------------- |
| 边端模组 | **Orin NX** Token 盒（可选 + 局部规划）                              | 吐标准化 spatial token  |
| 协同网关 | **今年 x86**；明年产品原型 **Jetson AGX Orin 64GB + 自研载板**（暂不上 Thor） | 多机 merge、全局图、VLA/调度 |


传感（激光/相机）继续用本体或第三方。【事实·架构与主规划 §3.5】  
外壳尺寸、供电、针脚、与宇树 Orin 舱叠装方式等【待补充】。

#### 3.4.4 真正壁垒（仓内诚实表述）【事实】

SLAM 引擎及内部 Local Map **不是**自有 IP。壁垒在：

1. Tokenizer 协议（谁先定 schema）；
2. 双触发关键帧等弱网流量 know-how；
3. SLAM↔VLA 下游对接中间件。

类比：SLAM≈MySQL，VLA≈GPT，motion≈ETL + 标准 schema。【事实·汇报 §2.5】

#### 3.4.5 按工作假设的「眸深–motion」分工


| 眸深                  | motion                       |
| ------------------- | ---------------------------- |
| 世界动作模型、跨本体大脑、端侧轻量推理 | 现场增量几何契约、弱网传输、多机网关、最小必要的数据回流 |
| 品牌：「具身大脑」           | 品牌：「空间增量协议 / 协同网关 / 大脑几何底座」  |
| 少依赖昂贵标注的训练策略        | 不与其域/MindCloud 比拼全量 3DGS 产线  |

## 6. 决策树：客户场景怎么选

```text
客户要什么？
├─ 工厂轮式 AMR 造车 + 整厂仓配调度、要工业认证交付
│     → 仙工（L0）
├─ 单机快速获得定位/建图/简单语言导航（尤其 Go2）
│     → 留形 Odin1 + Nav-Stack（L1）
├─ 大规模重建、3DGS 孪生、标注、VLA 训练资产库
│     → MindCloud / 其域 / 如视等（L2）
├─ 跨本体动作生成、世界模型大脑、持续进化
│     → 眸深等（L3）
└─ 弱网/无 GPS、多机在线共享增量几何、SLAM 要标准喂给大脑、断网仍安全
      → motion（L4 + 运行时数据管线）；前端可接 Odin/自研 LIO，大脑可接眸深
```

**推荐竞合链（推断）：**

```text
Odin1 或 Super-LIO（L1）
    → motion Adapter / Token 盒（运行时管线）
        → motion x86/Orin 网关（L4）
            → 眸深 HL3DWM / VLA（L3）
（离线孪生/重标注可外采 MindCloud 或其它 L2，而非自建第二条重建云）
```

## 7. 战略判断（细项）

### 7.1 组合位仍然稀缺

多数玩家只做 A（资产/Real2Sim）或只做 B（运行时调度/自治）。  
motion 若坚持「在线几何契约 + 弱网多机 + 喂眸深大脑」，属于**组合差异化**。【推断】

### 7.2 对留形：主战场是 MindCloud，不是 Odin1

- Odin：前端竞合。  
- MindCloud：会在「多机记忆 / 喂 VLA」话术上抢预算。  
- **禁止**用 3DGS 保真、10:1 重建效率硬刚；改用带宽、关键帧延迟、断连恢复、与眸深模型原生接口。【判断】

### 7.3 对眸深：补链而非分权

与陈涛「产业分工、聚焦世界动作模型」公开观点相容。【事实+推断】  
motion 对内是几何底座与现场协同；对外可单独卖网关/协议，但品牌不抢「大脑」。

### 7.4 国际对标优先级


| 要证明的能力                 | 优先对标                    |
| ---------------------- | ----------------------- |
| 无预建图、GPS-denied、多机共享环境 | FieldAI                 |
| 可查询增量共享空间索引            | Roam                    |
| 空间资产/3DGS/Isaac 工作流    | 其域 / MindCloud / 如视（知彼） |
| 工厂调度交付                 | 仙工（叙事靶）                 |


### 7.5 最大风险：两头都做不深


| 风险    | 表现                         | 缓解                           |
| ----- | -------------------------- | ---------------------------- |
| 产品膨胀  | 同时追全量 3DGS 云 + FieldAI 级自治 | **先 L4 可测，再最小 L3 回流**        |
| 叙事被吞  | 被听成「又一个空间记忆/MindCloud」     | 强制使用 §2.2 消歧话术               |
| 与母体抢词 | 与 HL3DWM「空间记忆」撞车           | 改称几何 Token / 网关 / 回流         |
| 证据真空  | 对手有展会与部署，己方仅 proposal      | 用眸深场景订单背书 + `40-验证` measured |


### 7.6 交付顺序建议【推断】

1. **P0 / L4**：Go2 双机（或仿真 Gate 后真机）+ x86 网关 + WiFi；量化 Token 带宽、断连恢复、Arrival/SR。
2. **与眸深接口**：Graph / SpatialChunk 检索上下文最小集，对齐 HL3DWM「先检索再聚合」消费方式。
3. **L3 数据回流最小集**：只做大脑迭代所需标注/片段，**不**自建对标其域的全量 Real2Sim 云。
4. **硬件盒 L3～L4 阶梯**：Orin NX Token 盒送测 → 切片 B → 明年 AGX Orin 网关原型。

### 7.7 定价与打包【推断】

- MindCloud 价封闭 → 空间平台多按项目/席位议价。  
- 眸深已有数据相关收入叙事。  
- motion 适合：  
  1. **绑售**眸深大脑交付的现场几何管线/网关；
  2. **单卖**协议 SDK + Token 盒给本体厂；
  3. **慎卖**纯 3DGS/标注 SaaS（除非明确外采 L2 伙伴）。

### 7.8 对外一句话（建议稿）


| 对比           | 建议表述                                                |
| ------------ | --------------------------------------------------- |
| vs 仙工        | 他们卖预建图工厂调度控制器；我们卖免预建图、弱网可降级的协同网关与语义任务原语             |
| vs Odin1     | 他们卖边端传感+闭源 SLAM（吐点云/位姿）；我们卖几何→标准 Token→多机/大脑的运行时中间层 |
| vs MindCloud | 他们做空间资产与训练回忆库；我们做现场弱网增量几何契约与断网安全闭环                  |
| vs 眸深（对外分工）  | 眸深提供具身大脑；motion 提供大脑所需的现场几何管线与多机协同网关                |
| 三者/四者错位      | 仙工管车队任务 · 留形管看见与资产 · 眸深管大脑 · motion 管弱网下几何如何标准流通    |
